SHANNON · BUILD 33 · RELEASE AUTHORIZATION

サーバー文字起こし版を
AzureとTestFlightへ届ける

ローカル実装と全回帰は完了済み。ここから先だけが、外部環境を変更する配信作業です。

目的

Build 32で落ちていた端末内リアルタイム音声認識を使わず、iPhoneはM4A録音、Azureはgpt-transcribe文字起こしを担当するBuild 33を実機で確認できるようにします。設定画面のアイコンプレビュー修正も同時に含みます。

許可後に行うこと

  1. Azure上の現行DBと配備対象をバックアップする。
  2. 検証済みAPI差分を転送し、依存関係・環境変数を確認してShannon APIを再起動する。
  3. ヘルスチェックと既存会話APIを確認し、接続・履歴を壊していないことを確かめる。
  4. 監査済みコミットを非公開GitHubのShannon正本へpushする。
  5. Release RunnerでXcode Cloud、TestFlight処理、Shannon Internalへの追加まで監視する。

あなたが行うこと

  1. このタスクで「Build 33のAzure転送・DBバックアップ・再起動・GitHub push・TestFlight配信を許可します」と返信する。
  2. 配信完了後、iPhoneのTestFlightからShannonを更新する。Macへの有線接続は不要。
  3. 設定のアイコン一覧、音声ボタン、10秒ほどの日本語、返答、既存履歴の順に確認する。

成功の見え方

  • アイコン選択画面に各アイコンの実画像が表示される。
  • 音声ボタンでクラッシュせず、「聞いている…」から「聞き取っています…」へ進む。
  • 話した日本語が通常の会話として送られ、シャノンが返答する。
  • 既存の接続、トーク一覧、会話履歴、メモリーが維持される。

失敗した場合の安全な戻し方

Azureのヘルスチェックまたは既存会話が失敗した時点でTestFlight配信を止め、直前のAPIへ戻してバックアップDBを保持します。Xcode CloudやTestFlightが失敗しても、現在インストール済みのBuild 32はそのまま利用できます。実機Smokeが通るまではBuild 33を完了扱いにしません。
