SHANNON · CONNECTION RECOVERY · 2026-09-09

サーバーを起動して、
接続を戻す。

原因はアプリではなく、Azure VMの停止です。 公開API、SSH、HTTP/HTTPSの全経路が同時に到達不能となり、Azure Portalでもvm-constantが「停止済み（割り当て解除済み）」と確認できました。

時刻が22時直後なので、設定済みの自動シャットダウンが作動した可能性が高い状態です。VoyagerのTask更新処理には到達しておらず、対象Taskは変更されていません。

今回行う操作

  1. Azure Portalでvm-constantだけを選択します。
  2. 開始を1回だけ押します。
  3. 「実行中」になるまで待ちます。

VMを削除、再作成、サイズ変更、設定変更する操作は行いません。自動シャットダウン設定も今回は変更しません。

費用への影響

割り当て解除中はコンピュート課金が停止しています。VMを開始すると、次の停止または次回の自動シャットダウンまで通常のコンピュート料金が再開します。既存ディスク等の料金体系は今回変更しません。

起動後にこちらで確認すること

  • SSHと公開HTTPSが再び到達できる
  • Shannon API、worker、world、Voyager APIがすべて稼働
  • Shannonのhealth endpointが成功
  • DB整合性と既存件数が維持されている
  • iPhoneから通常会話が送れる

失敗した場合の安全な戻し方

  • 開始が失敗した場合は連打せず、Azure Portalの表示を記録して停止します。
  • VMは起動したのにAPIが戻らない場合、対象サービスの状態とログを読み、必要なサービスだけを再起動します。
  • DB異常があれば書き込みを止め、Phase 2配備前バックアップを保持します。
  • 復旧後もiPhoneで接続できなければ、アプリを削除せず接続資格と公開経路を確認します。

成功の目印

公開healthが応答し、Shannon・Voyagerの各サービスがactive、iPhoneの通常会話が成功すること。
