# 声の発話に返事が必要か（2026-10-31、反映前）

持ち主の指定: 音声会話中も発話ごとに「返事する必要があるか」を判定する。名前なしの会話を残して誤反応を減らす。会話が開いていることや、直前に返事したことだけで次の発話を通さない。

判定は `services/api/src/mind/perception/addressed.ts` に集約する。Discord音声、Windowsの `/v1/voice/listen`、`/v1/voice/addressed` が共通に使うため、この変更は全ての入口に適用される。

## 判定

1. 名前の表記揺れを正規化する。名前だけの明確な呼びかけは規則で通す。持ち主が停止を求め、シャノンが話しているか体のタスクが動いている場合も、名前なしで停止を受け付ける。
2. 名前がある発話・同じ話者への返事から20秒以内の続きはJevに問い合わせる。持ち主ひとりの場合は、その外でも名前なしの質問・依頼を判定する。同席者がいる場では、名前も続きの文脈もない発話を通さない。
3. 質問セットは `addressed.v11`、既定400ms。1回の問い合わせで `addressed_to_shannon`、`target`、`about_the_job`、`answers_her_question`、`introduces_her`、`reply_needed` の6問を聞く（`about_the_job` は作業中の名前なしの発話だけ（彼女の直前の言葉から 20 秒の窓の中でも。自分の実況で窓はほぼ開いたままになるため、窓の中で一般の問いが「いいえ」でも、作業の話と読めば取る）、`answers_her_question` は自分の問いかけの後の名前なしの発話だけが読む）。宛先は `shannon` が必須（`unclear` は通さない）。宛先の確信値は通常0.7以上、名前なしで窓の外なら0.8以上。返事の必要性は0.8以上を要する。紹介（そこにいる人へシャノンを引き合わせる言葉）は人々の前で言われるため、`target` が `other_person` でも `introduces_her` が0.8以上なら宛先は彼女とする（`about_shannon`・`self` は覆さない）。`introduces_her` が0.7以上で返事する時は、判定の結果 `introduced` が返事を書くモデルへ渡り、プロンプトに「いま、ボクはそこにいる人たちに紹介された」の欄（聞こえた言葉・呼ぶ人の名前・収録中なら視聴者）が入る。返事するかどうかは変えない。この読み替えと欄は Discord の通話（`AddressedInput.presentation`）だけで効き、聴き流しなど他の入口は変えない。押して話す言葉（`directed`）は判定を通らないので、同じ事実（呼ぶ人・視聴者）を「紹介の言葉か挨拶の頼みなら」という条件の欄（`greetingHintBlock`）にして渡す。
4. 独り言、読み上げ、実況、発言者自身が答えたり撤回したりした質問、会話を閉じる相づちには返事しない。明確にシャノンへの質問・依頼なら名前なしでも通す。
5. 鍵なし・失敗・期限切れ・使用できない答えでは `addressed: false`。名前や直近の会話だけを根拠に通す控えは廃止した。`source: fallback` は許可ではない。`no_reply_needed` は宛先が合っても返事不要、`unconfirmed` は判定不能を表す（名前なしの新規発話は既存の `no_name`）。

20秒は `SHANNON_ADDRESSED_WINDOW_SECONDS`。端末が伝えた読み上げ終了からの経過、または頭の直前の返事と読み上げ時間の見込みを文脈に使う。窓の内側も自動許可にはしない。

## 送信と保持

Windowsからは判定する発話本文、経過時間、直前の返事、同席者・発話中の情報を送る。本文は判定だけに使い、判定経路では会話・記憶・本文つきログへ保存しない。Jevのキャッシュは秘密値でソルトを付けた要約値を鍵にする。判断の記録も宛先・確信値・名前の有無・続きかどうかなど、本文を持たない。Discordの直近3分の会話文脈はサーバーのメモリ内だけに保持し、再起動で失われる。応答することになった発話の通常の会話保存とは別の経路である。

## Windowsの受け口

`POST /v1/voice/addressed` は端末のトークンを要する。本文は `{ text, shannonSpokeMsAgo?, lastLine?, guest?, speaking? }`。textは1〜1,000文字。

200の答えは `{ addressed, reason, source, asked, ms }`。sourceは `rule` / `jev` / `fallback`。無効なら503 `ADDRESSED_DISABLED`、認証不可403、不正な本文400、端末ごと毎分30回を超えると429。新しいWindows候補は、無効・未対応・失敗時に会話を始めず、会話中も返事を生成しない。古いWindowsは控えの扱いが異なるため、PCと頭の双方を更新する。

`SHANNON_ADDRESSED` の既定は切。既存の本番では入を読み取り確認済み。環境変数・鍵はこの変更では書き換えない。

## 検証の範囲

通常のテストはJevの代役を使い、質問の内容・閾値・毎回の判定・失敗時の沈黙を確かめる。合格率は実モデルの精度ではない。`test:llm-addressed` は実モデルを呼んで費用が出るため今回実施しない。実際の誤反応率と取りこぼし率は未測定。厳しくしたことで、曖昧な話しかけを拾わない可能性がある。

## 作業中と、自分の問いかけの直後（2026-11-22）

- 作業中（依頼が実行中か列で待ち）は、名前なし・同席者ありでも Jev に聞く（`work`）。依頼・提案・作業への問いは宛先 shannon になり得る。宛先の問い（`target`・`reply_needed`）は読まず、`about_the_job`（その発話が作業への依頼・提案・問い・材料の入れ知恵か）が 0.4 以上なら受ける。理由は `asked_while_working`。作業に関係ない人どうしの雑談は黙る。本物の Jev（2026-11-22）は、部屋に向けた作業の入れ知恵を「別の人宛て」、提案を「返事が要らない」と読んで 作業の依頼・提案・入れ知恵 9 件中 7 件を落とした。`about_the_job` は作業の話が 0.5〜0.98、雑談が 0.01〜0.20 で分かれたので、基準をその間に置いた。
- 自分の直前の発話が問いかけ（`endsAsQuestion`。独り言の口の発話を含む）なら、45 秒以内の名前なしの発話は、Jev に「その問いへの答えか」を聞いて決める（`answers_her_question`、理由 `answer_to_question`）。Jev には問いの文そのもの（`shannon_question`、長い行は末尾 160 字）を渡し、短い・指示語だけ・聞き返しも答えとして読み、人どうしの雑談・別の人への呼びかけ・独り言・コメント読みは答えにしない。基準は 0.4 以上（取りこぼしのほうが高くつくため低め。本物の Jev での測定はまだ）。窓は 45 秒のまま。作業中（`work` がある時）は、答えか、作業の話（`about_the_job` が 0.4 以上、理由 `asked_while_working`）か、どちらかで受ける（問いの後に来る作業の入れ知恵が落ちないように。同じ 1 回の問い合わせの中の答えを使う）。口の発話は全員宛て、返事の問いは相手の人宛て。名前つきの発話は従来どおり答えとして受ける。Jev が時間内に答えない・鍵がない時は、従来どおり答えとして受ける（本当の答えを落とさない側に倒す。ここだけ `source: fallback` が許可になる）。問いが閉じるのは、シャノンが受けた発話があった時だけで、答えでないと判定された雑談では閉じず、本当の答えを待つ。
- 声のターンに `speakerMinecraftName`（旧形は最上位、一頭形は `who`）があれば、依頼の `speaker.minecraftName` へ運ぶ。
- 押して話した発話（`directed`。旧形は最上位の欄、一頭形は `presence.directed`）は、名前がなくても答える（理由 `directed`）。`SHANNON_ADDRESSED` の入切に関わらず、Jev にも聞かない。ただし息・キーの音・単独の「うん」のような断片（`voiceFragment`）は押しても返事にしない（直前に彼女が話した直後の「うん」だけは答え）。判断を書き換えるのではなく「話しかけた」という事実を入力に足す形で、頭のプロンプトは変えない。印がない時は従来どおり。
- 持ち主の印（`speakerIsOwner`。旧形は最上位、一頭形は `who`。真の時だけ送る）：体が「この話者は持ち主」と確かめた印。頭は、話者の ID と人の一覧にある同じ ID を、会話の束縛の持ち主の ID に置き換えてから判定する（持ち主の依頼として通り、持ち主は 1 人として数える）。頭が持ち主を推測する道は足さない。印が無い時は従来どおり、知らない ID は客。
- 彼女の返事に重なって話された発話（`speakingNow` が真）：答えると決めて decision 行を出した後、同じ部屋の「返事が途中で止まった」知らせ（`said` の `source=reply`・`interrupted=true`）を最大 1 秒待ってから履歴を読む（`PLATFORM_VOICE_LIMITS.cutShortWaitMilliseconds`）。知らせが来なければそのまま進む。
