# Aether access: the Shannon side

Contract: `syzygy.aether-shannon-access.v1` (Syzygy hub `contracts/aether-shannon/README.md`) and knowledge search v1 with the optional `scope`, `inShannonFolder` and `inStudy` (hub `contracts/knowledge/`).
Authority: Syzygy ADR-0007 and its revision of 2026-10-06 (owner decision). Shannon is the consumer; Aether is the provider.
State: implemented on the server behind configuration; the apps' screens are unchanged (see "What the apps may change").

## Words

- **シャノン用フォルダ**: where she keeps documents, code and files freely. Three places: one Aether folder (`project_shannon_folder`), and her folders on the owner's Windows PC and MacBook (`docs/host-folder-contract.md`).
- **シャノンの書斎**: her stories. Only in Aether: documents tagged 「書斎」 (type `story`) in the Aether シャノン用フォルダ. That is the canonical copy. Stories are never put in the PC or Mac folder.

## Configuration

| Variable | Meaning |
| --- | --- |
| `SHANNON_AETHER_API_URL` | The Aether authenticated API (`http://127.0.0.1:3007` on the VM, or the public `/aether` path). `https` is required except to this machine (`127.0.0.1`, `localhost`, `[::1]`); any other `http` address leaves the client off. |
| `SHANNON_AETHER_SHANNON_TOKEN` | The Shannon-scoped token (`node scripts/mobile-auth.cjs issue-shannon-token` on the VM, owner-approved). Never logged, never in an error. |
| `SHANNON_AETHER_TIMEOUT_MS` | One request's timeout, 500–60,000 ms (default 8,000). |
| `SHANNON_AETHER_PROPOSAL_DIR` | The proposal inbox (unchanged; v2 adds `update` and `delete`). |
| `SHANNON_AUTONOMY_OWNER_DOCUMENTS` | Autonomy service only: `on` lets her own time read the owner's documents (`ownerDocs.*`, below). Unset, `off` or anything else: off. |

With the URL or the token unset there is no client (`configuredAetherAccess` returns null): no Aether tool is offered, her study is the SQLite study, the app routes answer exactly as before, and the copy step of her own time is what it was. Set both alike for the API (`server.ts`) and the autonomy service (`autonomyWorker.ts`); the autonomy service never gets the proposal inbox.

## The client (`services/api/src/aetherAccess.ts`)

- `POST api/shannon/v1/knowledge-search`: the knowledge search v1 envelope, `scope` sent unless `all`; the response is parsed by `aetherKnowledgeSearch.ts` and fails closed on any unknown field or another contract.
- `POST api/shannon/v1/document` `read`: `{documentId, offset?, maxChars?}` (1–20,000 code points) or `{documentId, sectionId}`. A missing `inShannonFolder` counts as outside her folder.
- `POST api/shannon/v1/folder` `list` / `create` / `update` / `delete` with `baseVersion` and `idempotencyKey` (`shannon.` + 48 hex characters of a SHA-256 over what makes the write the same write).
- Every response must carry this contract and the expected `kind`; anything else is `CONTRACT_MISMATCH`. Redirects are refused; a response over 4 MB is refused.

| Provider answer | Shannon code | Her tool result |
| --- | --- | --- |
| 409 `STALE_VERSION` | `STALE_VERSION` | `conflict`: read again, write from the new version |
| 403 `OUTSIDE_SHANNON_FOLDER` | `OUTSIDE_SHANNON_FOLDER` | `refused`: propose with `aether.propose` |
| 404 / `NOT_FOUND` | `NOT_FOUND` | `not_found` |
| 409 `IDEMPOTENCY_KEY_REUSED` | `IDEMPOTENCY_KEY_REUSED` | `conflict` |
| 400 / 413 / `INVALID_REQUEST` | `INVALID_REQUEST` | `invalid_input` |
| 401 / other 403 | `UNAUTHORIZED` | `unavailable` (token) |
| timeout | `TIMEOUT` | `timeout`, retryable |
| network, 5xx | `UNAVAILABLE` | `unavailable`, retryable |
| another contract or shape | `CONTRACT_MISMATCH` | `unavailable` |
| (gate) a document outside her folder with others present | `OUTSIDE_AUDIENCE` | `refused`: with the owner alone |
| (gate) a document she wrote after reading the owner's, with others present | `OWNER_INFORMED` | `refused`: with the owner alone |

## Her tools (`shannonTools.ts`, `shannonAetherTools.ts`)

| Tool | Effect | Audiences | Surfaces |
| --- | --- | --- | --- |
| `aether.search` (`query`, `scope`, `limit`) | read | owner alone, others | text, voice, own time |
| `aether.read` (`documentId`, `offset`, `maxChars`, `sectionId`) | read | owner alone, others | text, voice, own time |
| `aetherFolder.list` | read | owner alone, others | text, voice, own time |
| `aetherFolder.create` / `update` / `delete` | write | owner alone | text, voice, own time |
| `aether.propose` (`operation`: new-note, append, update, delete) | write | owner alone | text, voice |
| `ownerDocs.search` / `ownerDocs.read` (with `pursuitId`) | read | owner alone | own time, while switched on |

Offered only while the Aether client is configured (address and token), and only to the owner's scope (`SHANNON_OWNER_SCOPE_KEY`, default `owner`; any other scope is neither offered nor allowed to call them, on every surface); `aether.propose` only while the inbox is configured as well. With the inbox alone, or the token alone (production before the owner approves the move), every tool definition, instruction and capability line is exactly what it was before Aether access (`aetherStudy.test.ts`, "a server with only part of Aether configured"); the Aether instruction and capability line are keyed to `aether.search` being offered. Gate domain `aether_study` (her own time) and `aether_proposal` (conversation only, never seen by the autonomy gate).

**Who may read what** is decided at the gate (`shannonToolGate.ts`), not in the prompt: with the owner alone in a conversation everything may be searched and read; with anyone else present (others in text, another voice, a call with someone listening, what the server knows of her body) and in her own time, `authorizeToolInput` refuses `aether.search` unless `scope` is `shannonFolder` or `study`, and `gatedAether` hands the executor a client that keeps only hits placed in her folder and reads a document only after a one-character read showed it is in her folder. In a turn with others present only these three reading tools are offered, with their own instruction (her stories and notes, unshown drafts included, may be read aloud there without his approval first, ADR-0007 revised 2026-10-06 (the app's study screen still hides an unshown story); a turn the owner did not speak or write is told this without presuming he is there, `TOOLS_GUESTS_INSTRUCTIONS`). A turn the owner did not speak or write (owner decision 2026-10-06, Syzygy ADR-0007; `ownerAlone: 'guests'`) is offered the same three tools and nothing else: a friend in 「友人も一緒」 (not a client that predates people memory) and someone else's turn on a platform reply (`othersFolderReading`, `platformReply.ts`); her Minecraft body's game chat keeps its rule (none). By a further owner decision of the same day the owner's own turns that others can read get the same three tools as `ownerAlone: 'shared'`: an app text turn marked `others` and his turn in a shared platform conversation; like `'guests'`, without Aether they get nothing and are told nothing, exactly as before. Such a turn opens no trace, and without Aether it gets nothing and is told nothing, exactly as before. **What she reads in front of others** (owner decision 2026-10-06, 「所有者の内緒・個人的なことを除いてから使う」): with anyone else present in a conversation the result of an Aether reading tool reaches the model as `resultForOthers` leaves it (`aetherShownText.ts`, applied by the gate's `shownAetherCall`), by the owner's word 「除く」, with the run check of `conversationSecrets.ts` applied to free text (`othersSecrets`, items judged by `disclosureDecision` for an unnamed guest, as memory judges them): a sentence carrying something withheld (secret, 機微 by hand, forgotten, or withheld for an unnamed guest) is left out, and so is one holding, whole, any sentence (cut at 。！？!? and line breaks) or finer fragment (also cut at ｡．、，, emoji and spaces next to non-ASCII text, e.g. 「来月に手術」) of four or more characters of such an item, with emoji variation selectors, joiners and skin-tone modifiers removed on both sides (an ASCII-only secret is not cut at `.`; the whole sentence still catches it, its parts do not); this path only; a fragment of five or fewer hiragana, such as 「そうなんだ」, is skipped as filler). Known usefulness limit: this fails safe and can over-remove, e.g. a short fragment of a secret that is a common word or a name (「シャノン」) takes out every sentence holding it; one carrying his other personal matters (guarded) is left out too, in every turn with others present (app text marked `others`, `'shared'`, voice with someone listening, 「友人も一緒」, someone else's platform turn; final review S-2), where memory would only mark it; where he may release a line (every such turn but someone else's platform turn, `openOnly`) the whole result, unlabelled derived text, also carries `UNLABELLED_DISCLOSURE_MARKER` on a line before it, so the speak-time check covers it; a line says that something was left out; a run across sentences (checked on the kept text without markers, final review S-1), or a check that cannot be read or is missing, gives nothing. Like every use of that check it catches his words and their ten-character runs, not a retelling; turns count whoever spoke them, an unlabelled (older) turn counts as guarded, and a text of four to nine characters must appear whole, so a short ordinary turn such as 「ありがとう」 may take a harmless sentence out of what a turn with others present reads (left so rather than weaken the check). Her `aether.*` tools read only her folder in her own time, because their gate domain is her study.

**The owner's documents in her own time** (owner decision 2026-10-06, Syzygy ADR-0007 「自分の時間に所有者の文書を読む」, every recommendation of the plan accepted): `ownerDocs.search` (`query`, `pursuitId`, `limit`; hits outside her folder) and `ownerDocs.read` (`documentId`, `pursuitId`, `offset`, `maxChars`, `sectionId`), surface `autonomy`, audience owner alone, core domain `owner_documents_read` (free, `packages/cognition/src/autonomy.ts`), executors `shannonOwnerDocumentTools.ts` over the client as it is. Offered only while `SHANNON_AUTONOMY_OWNER_DOCUMENTS=on` and her Aether tools exist for the scope; otherwise not known on any surface, and every tool, prompt and the policy context is what it was (`ownerDocumentsOwnTime.test.ts` pins her own time's prompts with tools and Aether wired). `pursuitId` must name a pursuit that is `active`, or the step reads nothing. What she reads stays in the loop's memory as 「[道具の結果]」 until her next thought; the record keeps a sentence and `aether://documents/<id>`. No count: the day's budget and the session's bounds hold it.

**The provenance mark** (`ownerInformedMarks.ts`, `autonomyLoopProvenance.ts`): the literal filter above cannot catch a retelling, so a session of her own time that reads one of his documents (a read, or a search with hits), a shared Notion page (whatever the switch says), or a document already marked gets `owner_informed_at` on its `autonomy_loop_cycles` row until it rests. What a marked session writes (a note, a jot, a draft, a revision, `study.create/update/rename`, `aetherFolder.create/update`) is a row of the append-only `owner_informed_documents` (its Aether document id, and `shannon-study://<piece>` for a piece of her study, so a piece that moves later stays marked), and a pursuit created or changed in it carries `owner_informed_at`. With anyone else present `gatedAether` leaves marked documents out of a search and a listing and refuses a read (`OWNER_INFORMED`), and a message of hers takes no marked note or story as material; her study tools are the owner's alone anyway, and a turn with others present is given none of her pursuits. The owner alone, her own time and the app's study screen are unchanged. A marked session, also one marked by a Notion page with the switch off (owner decision 2026-10-06), holds a message to the owner (a message, a second call, a phone call) while anyone else may see or hear her body, also when someone comes while its words are written, and the gate refuses `reachesOthers` and the domain `outreach` outright (`owner_informed`). A marked session also keeps no words of her thought or of her reason for resting in the record or the session row, writes nothing into her folder on the owner's PC or Mac (those files are not marked), and marks what Aether takes the moment Aether answers, so a report that fails later leaves nothing unmarked. A search or a listing of her own time that shows a marked document marks the session, as a read does.

**Prompts of a session that is not marked** (owner decision 2026-10-06, option (a); `unmarkedOnly`, `unmarkedPursuits`): its thinking, note, draft, revise, message and phone prompts are given no marked note or piece body, no marked story (title, change notes), no marked pursuit, and not the reason a marked session gave for resting; with anyone else present a message or a call is given nothing marked, whatever the session. Opening a marked piece on purpose (`study.read`, `aether.read`, revising it) marks the session, and a marked session is given everything as before. While nothing is marked nothing is looked up and every prompt is what it was (`ownerDocumentsOwnTime.test.ts`). Because a note after a shared Notion page is marked whatever the switch says, her own later sessions that are not marked are no longer given that note or a story written in that session, also with the switch off: the owner accepted this with option (a). `autonomyLoopKillSwitch.test.ts` holds the day of the commit before with that mark set aside, byte for byte, and the day as it runs with it. Only ids and times are stored, never a word of a document. Taking a mark off is a later step (ADR-0007).

Nothing she reads is stored: results live in the turn (or until her next thought in her own time), traces keep ids and counts only, and the activity record names no document text and no title of her study.

## Her study in Aether (`studyAether.ts`, `studyAetherLinks.ts`)

- One scope only: the owner's (`SHANNON_OWNER_SCOPE_KEY`, default `owner`; `aetherStudyScope`). Aether has one シャノン用フォルダ, so sync, adoption, the study tools' Aether writes, the app routes' Aether reads and the migration act for that scope alone; every other scope keeps the SQLite study exactly as before.

- A story is a document with `inStudy: true` (tag 書斎, type `story`); a note one with `inStudy: false`. Her notes about a look at the room and what she jotted after an unanswered message never move (with others present her Aether folder may be read).
- A write goes to Aether first (create, or update with `baseVersion` = the Aether version she last saw, or delete into Recently Deleted), then her local version and its link commit in the transaction that records the step or call. Aether refused: nothing is written in Shannon. A stale version brings the newer Aether text in as her next local version (change note 「Aetherの側で変わった版です…」) before the write fails, so the next try starts from it.
- The moment Aether takes a write it is noted in `study_aether_pending` (document, version, her kind and change note), and the local commit clears it. A write noted less than two minutes ago is still committing in its own transaction, so a sync leaves its document and version to it; and a commit that finds the document already another piece's, or the version already linked, is refused (`STUDY_AETHER_LINKED`) and leaves no second piece or version. A write whose local half was lost is linked by a later sync as hers: a note as a note, a story within the open-story limit (put away when her open stories are full), with her own change note, never as a change of the owner's. Only a process that stops between Aether's answer and that note leaves an unknown document: a story in her study is then adopted like one the owner put there, a note stays a document of her folder.
- `study_aether_links` (insert-only): local version ↔ Aether document and version. Shannon keeps what Aether does not: the stage (下書き, 見せてもいい, 見せた, しまった), the version the owner reads, every version with what changed and why, and the owner's reactions (`study_feedback.aether_document_id`, `aether_version`).
- Every study tool call first syncs (`StudyAether.sync`, at most 4 s; one run per scope at a time in a process, shared by callers that come while it runs; a version is adopted only when, read again inside the transaction, the link is still older than it): newer Aether versions are adopted, a document gone from Aether, or moved out of her folder (Aether answers it with `inShannonFolder: false`), puts the piece in her trash and nothing of its text is kept, one the owner restored takes it back out, a write of hers whose local half was lost is linked as hers (above), and another unknown story in her study is adopted as a draft (or put away at the open-story limit). Unreachable Aether: reads answer from Shannon's copy and say so; writes fail.
- A write of hers that Aether answers with `OUTSIDE_SHANNON_FOLDER` (the owner moved the document into his own documents) is handled like a deleted document: the piece goes to her trash, nothing is adopted, and her own time stops planning it; her delete of such a piece is done in Shannon only.
- A study document longer than Shannon reads whole (100,000 characters) is never taken in cut short: the sync skips it with the code `too_long` (in its result) and notes it in `study_aether_too_long` (document, version, piece; the diagnostic record, read by every process). Her write to such a piece is refused before anything is sent, and her tool says so plainly (`limit`, 「長すぎて…」); her own time plans no revision of it, so no paid call is made. The note is cleared once the document reads whole again.
- A document of her study that she changes with `aetherFolder.update` is taken in at once as her own version (change note 「シャノン用フォルダの道具で書き換えました。」), never later as the owner's change.
- `study.restore` of a piece in Aether is refused: the owner restores it in Aether (Recently Deleted on iPhone, or by moving it back into her folder), and the next sync brings it back.
- Her own time: `note`, `draft` and `revise` write to Aether first (`aether_*` reason codes when they cannot); `show` and `put_away` change Shannon's stage only. The v1 step that copies a piece to the PC folder is neither offered nor prepared while Aether is configured, and her folder tools refuse a file that carries a run of one of her stories.
- A piece that has not moved yet (no link) stays in Shannon and is written there until the migration moves it.

## App-facing routes (unchanged paths, additive fields)

- `GET /v1/autonomy/study`: with Aether, syncs first (4 s; a sync of the scope that finished in the last 2 s serves as it is, and one in flight is shared), then the same body plus `source: { kind: "aether", reached }`. Each readable card may carry `aetherDocumentId` and `aetherVersion` (the Aether version of the version he reads). A hidden card carries neither.
- `GET /v1/autonomy/study/pieces/{id}`: `{id}` may be the piece id or its Aether document id; refreshes that piece first. `feedback[]` items may carry `aetherDocumentId`, `aetherVersion`.
- `POST …/{id}/reaction` and `POST …/{id}/put-away`: `{id}` as above; the reaction is stored in Shannon with the Aether document and version.
- Piece ids, `shannon-study://<id>` links in her messages, and every existing field keep their meaning.

## Migration (`services/api/scripts/migrate-study-to-aether.ts`, `studyMigration.ts`)

`pnpm --filter @shannon/api migrate:study-to-aether` (dry run) prints, per scope, the counts and one line per piece (every piece, no cap): kind, title, length, stage, whether the owner has seen it, and where it goes (or why it stays). No body is printed or read (the length comes from SQLite). The titles of pieces in her trash and of pieces that stay in Shannon are left out (「（題名は伏せる）」); an unshown draft keeps its title, because the owner reads this list to see what moves. The dry run opens the database read-only (`readOnlyMigrationPlan`): it creates no table, adds no column and writes nothing, also on a database that predates the study's Aether tables, so it is safe against production. Back up the database before `--apply`, which opens it read-write and adds those tables. Order of the move: (1) dry run, shown to the owner; (2) stop the API and the autonomy service, and keep both stopped until step 5; (3) back up the database; (4) `--apply --services-stopped` (the flag is required, and the script refuses while the autonomy loop's runner reported in the last five minutes; the API cannot be checked this way); (5) set `SHANNON_AETHER_API_URL` for both services, run `--apply --services-stopped` once more right before starting them (a moved piece revised or put in her trash in Shannon since is sent to Aether from the version Aether has, keyed by piece and version; a delete is sent once and noted in `study_aether_deletions`, so a later run never deletes again a document the owner restored from Recently Deleted, and runs that send nothing add no line to the activity record; a change the owner made in Aether meanwhile is not overwritten and is reported as `aether_stale_version`), then start both. A service syncing her study during the move could take a moved story in as a second piece, which the migration reports as `document_taken`. `--apply` (Aether configured) creates one document per piece from its current version with the key `study / scope / migration / piece / version`, links it, names its reactions' document, and appends one line to the activity record. Run again after an interruption; nothing moves twice. Only the owner's scope moves (`--scope` may only name it); `--database` points at another file. Back up the database first; show the owner the dry run before `--apply`.

## What the apps may change (next step)

See the report of this change in the Syzygy hub; in short: read `source.reached` to say when Aether could not be reached, keep using piece ids, optionally open a story in Aether by `aetherDocumentId`, and show that a deleted story is restored from Aether's Recently Deleted.

- A `restore` kind, if Shannon should take a piece back out of Recently Deleted herself.
