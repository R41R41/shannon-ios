なぜ起きたか

  1. 整理AIの出力形式がtitleとdetailsだけで、新規作成か更新か、対象名、変更する項目を分離していません。
  2. 整理AIへの指示も「行動をVoyager Task案へ変換する」という新規Task向けのままで、更新依頼を「更新作業」というTaskに言い換えました。
  3. 確認画面で既存Taskを選んでも、編集欄を対象Taskの現在値へ戻さず、整理AIが作った汎用タイトルと操作手順を保持しました。
  4. 最終送信は編集欄のタイトルを常に変更値として扱うため、対象Taskのタイトルまで書き換えました。
  5. 「合うProjectを選びたい」という意図があるのに、Project未選択のまま反映できました。

正常に働いた安全機構

  • 対象Task IDは正しく、別Taskは変更していません。
  • 期待revision 1からrevision 2への1回だけの更新です。
  • 同一要求の重複防止記録が残り、二重更新はありません。
  • 変更前スナップショットがShannon DBに残っており、正確な復元が可能です。

推奨する復旧順

  1. 対象Taskを変更前へ復元：タイトル、詳細、Projectなしをrevision 2に対する安全な更新で戻す。
  2. Phase 2の本番利用を一時停止：修正版が入るまで、既存Task更新を再試行しない。
  3. 構造を修正：整理結果をoperation / targetQuery / changesへ分離し、変更しない項目は送信しない。
  4. 確認画面を修正：対象選択時に現在値を基準へ置き、項目別の変更前後を表示。意図しないタイトル変更を警告する。
  5. Project選択を必須化：Project選択を依頼した整理案は、Projectか「今回はProjectなし」を明示するまで反映不可にする。
  6. 同じ文章を回帰試験：今回の実文をfixture化し、タイトル維持、詳細だけ変更、承認前無変更、1回だけ反映を検証してから再配備する。

復元に失敗した場合

revisionが2から変わっていれば自動上書きせず停止します。現在のVoyager値を再取得し、ユーザーへ新しい差分を見せてから判断します。DBを直接編集したり、別Taskを作って帳尻を合わせたりはしません。
