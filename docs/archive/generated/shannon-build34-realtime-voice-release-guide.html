SHANNON · NEXT TESTFLIGHT

Realtime音声を
実機へ届ける。

発話中字幕、シャノンの音声返答、自然な割り込み、既存トークへの保存を、次の内部Buildで確認するための配信手順です。Build 33の会話・接続・DBは消しません。

何を変更するか

  • Azure APIに、ペアリング済みiPhone専用のRealtime call作成口を追加
  • iPhoneの音声ボタンを、一括M4A送信からWebRTC音声セッションへ変更
  • ユーザーとシャノン双方の字幕を発話中から表示
  • 確定した一往復だけを現在のトークへ保存し、感情・記憶は従来どおり非同期更新
  • OpenAI標準APIキーはAzureの外へ出さない

こちらで行うこと

1
正本と差分を固定
shannon-iosだけを対象にし、既存の無関係な変更を分離して監査します。
2
Azureを安全に更新
オンライン整合DBバックアップと変更前ソースを保存し、APIだけを更新。型検査、DB integrity、既存件数、3サービス、通常会話を確認します。
3
GitHubとXcode Cloud
検証済みcommitを非force pushし、既存のRelease RunnerでArchive、Upload、Apple Processing、Shannon Internal割当まで監視します。
4
実機Smoke
TestFlightで更新後、下記5項目だけを確認します。

ユーザーがすること

配信前：この会話で次の一文を返信します。

Realtime音声版のAzure転送・DBバックアップ・再起動・GitHub push・TestFlight配信を許可します

配信後：TestFlightでShannonを更新し、音声ボタンを一度タップします。iPhoneをMacへ接続する必要はありません。

成功の見え方

  1. 音声画面が開き「聞いている」になる
  2. 話している途中から「あなた」の字幕が伸びる
  3. シャノンが音声で返し、返答字幕も同時に伸びる
  4. 返答中に話すとシャノンが止まり、聞く側へ戻る
  5. 終了後、トーク画面に確定した会話が残る

失敗した場合の安全な戻し方

  • Azure更新で異常：TestFlight配信へ進まず、保存した変更前APIへ戻します。DBバックアップは保持します。
  • Xcode Cloud失敗：現在のBuild 33はそのまま利用できます。GitHubをforce操作しません。
  • 音声だけ失敗：通常の文字チャットは維持。アプリを削除・再ペアリングせず、設定 → 音声診断を共有します。
  • 費用保護：初期版は明示起動、端末別接続制限、1回10分上限。一般利用前にAzure側の日次Realtime予算を追加します。
