Shannon · TestFlight Build 38

未完成の音声接続情報を
送らないようにする

Build 37は、iPhoneが接続候補を集めている途中のSDPをOpenAIへ送り、invalid_offerになっていました。Build 38では候補収集の完了を待ってから送信します。

1

今回の変更

ICE候補を一度だけ収集し、完了まで最大10秒待ってからAzureへ送ります。

2

安全な診断

SDP本文は保存せず、音声・データ欄・候補の個数だけを診断ログへ残します。

3

変えないもの

Azure API、会話DB、認証、既存トーク、App Iconは変更しません。

こちらで必要な操作

GitHubの非公開リポジトリへ検証済みcommitを送り、既存のXcode CloudとShannon Internalを使ってBuild 38を配信します。

許可する場合：「Build 38のGitHub pushとTestFlight配信を許可します」と返信してください。

配信後、あなたにお願いする確認

  1. TestFlightでShannonを削除せず上書き更新する。
  2. 既存トークと接続が残っていることを確認する。
  3. 音声ボタンを押し、接続後に短く話す。
  4. 自分の発話字幕、シャノンの字幕と音声が出ることを確認する。

成功：接続が成立し、話した内容がリアルタイム表示され、シャノンが音声で返答します。

うまくいかなかった場合

現在のBuild 37はそのまま残ります。会話DBや認証は変更しないため、再インストールは不要です。

設定 → 音声診断 → コピーを選び、ログを共有してください。新しいログには audio_sections、data_sections、candidates が入り、次の原因を一度で判定できます。
