SHANNON · VOICE V1 · BUILD 33 DESIGN

iPhoneは録音と送信だけ。
文字起こしはAzureで行う。

Build 32までのクラッシュ経路を外し、まず確実に「話す → 文字になる → シャノンが答える」を成立させる。

推奨：サーバー文字起こしをv1の標準にする

判断

サーバー方式

端末は短いM4Aを録音して送るだけ。実装が単純で、認識品質も端末差を受けにくい。

端末内SpeechAnalyzer

通信・従量費・音声送信は不要。ただし現在は録音callback境界でクラッシュし、Speech APIとSwift 6の隔離境界を同時に扱っている。

「処理が重い」ことは悪化要因。ただし軽い受け渡しだけだったBuild 29でも同地点で落ちたため、端末性能だけが原因ではない。ログ上はengine開始後、最初のaudio callbackが動く境目で終了している。

端末側の体験

状態表示処理
録音中経過時間、簡単な音量反応、停止ボタンM4Aへ保存。逐次文字起こしはしない
停止後「聞き取っています…」認証付きでAzureへ送信
成功入力欄へ文字を表示して送信既存のFCA会話へ渡す
失敗再試行／録り直す通常の文字入力は常に利用可能

安全・費用の境界

  • 1回60秒、5MBまで。長時間録音や無制限再試行を防ぐ。
  • ペアリング済み端末だけ利用可。音声専用の回数制限と日次予算を持つ。
  • 端末・Azureとも、文字起こし完了または失敗後に一時音声を削除する。
  • 診断ログには音声・文字起こし本文・認証情報を残さない。
  • 会話、睡眠バッチ、音声文字起こしの費用を別レーンで記録する。
  • 最初は gpt-transcribe。音声専用レーンへ実利用時間と推定費用を記録する。

OpenAI公式：GPT-Transcribe ／ ファイル文字起こしガイド ／ エンドポイント別データ管理

OpenAI文字起こしモデル比較

モデル用途・価格Shannonでの判断
gpt-transcribe完了ファイル／逐次入力、高精度、固有語・言語ヒント。$0.0045/分（1時間 $0.27）Build 33で採用
gpt-live-transcribe低遅延の逐次字幕。$0.017/分（1時間 $1.02）将来、話しながら文字が出る体験を作る時
gpt-realtime-whisper遅延と精度を調整するStreaming。$0.017/分（1時間 $1.02）今回は不要。Live版との比較候補
gpt-4o-transcribeWhisperより高精度。音声入力$2.50/100万token、出力$10/100万token比較評価用の候補
gpt-4o-mini-transcribeWhisperより高精度。音声入力$1.25/100万token、出力$5/100万token旧候補。現行標準にはしない
gpt-4o-transcribe-diarize話者分離。音声入力$2.50/100万token、出力$10/100万token一人で話すShannon入力には過剰
whisper-1従来の汎用文字起こし／英訳・言語識別。$0.006/分（1時間 $0.36）英訳または既存互換が必要な時

結論：今のShannonは「話し終えてから送る」方式なので、最安で用途にも合う gpt-transcribe が第一候補。ライブ字幕化するときだけ、約3.8倍の単価を受け入れて gpt-live-transcribe を評価する。
