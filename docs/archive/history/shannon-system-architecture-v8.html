ひとつの人格が、複数の会話と外の世界を生きる。

ShannonのiOS体験、FCA、連続感情、ユーザー知識、睡眠、自律探索を、ひとつの共有状態を中心に組み直す。返答は速く、成長は背後で続く。

03 / Runtime lanes

速い返答と、遅い成長を分離する

返答中に感情や記憶が書き換わっても、その返答は開始時のsnapshotを使い切る。完了した更新は次の返答から効く。

Flow
iOS
API
Cognition / LLM
SQLite
Worker
A. 返答FCA
同期・最優先
1. 送信threadIdと本文をHTTPSで送る。
2. snapshot取得共有状態versionを固定し、直近履歴を取得。
3. Prompt → LLM固定核・状態・知識投影・履歴を結合。
4. 会話を保存user/assistant、表情、stateVersionを記録。
5. job投入返答を待たせず背景更新を予約。
B. 即時学習
非同期・数秒
返答はすでに表示
1. jobを受理experienceIdで重複実行を防ぐ。
2. 明示事実を抽出本人・時制・否定・訂正を構造化。
3. QAを更新根拠とrevisionを保存しsnapshotを再構築。
4. 感情・興味scopeごとに直列適用。次のFCAから有効。
C. 手動編集
同期・確認済み
1. 知識を編集回答の追加・訂正・削除を行う。
2. 検証question key、長さ、対象ユーザーを確認。
LLM判定は不要
3. revision保存source=user_manual、confidence=1.0。
4. 投影更新即時にprompt snapshotへ反映。
D. 睡眠
夜間・1日1回
端末は閉じてよい
1. 日次範囲確定同一日・scopeを一度だけ処理。
2. 一日を振り返る会話・活動・反例をまとめる。
3. 差分だけ保存性格分析、弱い仮説、興味をversion化。
4. 活動記録睡眠結果をメモリー画面へ残す。
重要：「想起」は自由文検索を返答中に走らせない。Workerが会話後にactive memoryとprompt projectionを更新する。返答FCAはそれを1回読むだけなので速度が安定する。
04 / FCA prompt

毎回、確定済みの自分を読む

全DBを巨大な文章へ圧縮しない。常時必要なものと、現在に関連するものを分離し、事前生成した投影を使う。

1. 固定核「シャノンという名前のAI」。最小限で基本的に変更しない。
2. 現在の自分感情、気質、興味、関係性。共有snapshotから取得。
3. ユーザー核呼び名、境界、重要な好みなど常時必要なQA。
4. Active Memory背景処理が前ターンまでに選んだ関連記憶と知識。
5. Thread Context現在トークの要約と直近メッセージだけ。
6. 今回の入力ユーザー本文。返答時の表情も同時に出力。

返答に影響する

共有感情、興味、確認済み知識、現在のトーク、active memory。

返答後に更新する

連続感情、明示知識、興味、活動記憶、次回のactive memory。

v1では存在しない

予測と予測誤差、毎日のfine-tuning、Aether連携、自己生成スキル。

06 / Database

SQLiteを、JSON倉庫から知識構造へ育てる

v1はAzure上のSQLite + WALを継続する。一人のShannonをAPIと直列Workerが扱う規模では十分。iOS側は表示キャッシュのみで、正本を持たない。

会話 Thread scoped

conversation_threadsタイトル、作成・更新、archive、要約
conversation_messagesthread、role、本文、表情、state version

知識 Shared

question_definitions質問key、カテゴリ、表示順、自由追加
knowledge_answers現在の回答、確信度、確認状態
knowledge_evidence会話・手動編集・推測の根拠
knowledge_revisions旧値と新値の改訂履歴

人格と生活 Shared

companion_states最新の確定済み共有snapshot
personality_profiles性格分析のversion履歴
interestsテーマ、強度、由来、減衰
activity_events睡眠、探索、購読、知識更新

外の世界 Untrusted

world_sourcesRSS、天気、HN、論文、SNS
subscriptions試読理由、期限、継続評価
world_items記事・投稿のmetadataとcontent hash
observationsシャノンの読後メモ。ユーザー事実ではない

実行基盤 Durable

background_jobslease、retry、dedupe、失敗理由
sleep_runs日次範囲、適用差分、完了状態
prompt_projectionsFCAが1回で読む事前生成profile
devices端末token、失効、最終接続

設計上の正本 Ownership

回答の正本knowledge_answers + revisions
人格の正本companion_states + events
会話の正本threads + messages
LLM入力prompt_projections。正本から再生成可能

08 / Build order

Coreを固めてから、世界を開く

各段階を大きめにまとめて実装し、テスト完了後に実機へ一括反映する。外部サービスを先に増やさず、人格とデータ境界を完成させる。
