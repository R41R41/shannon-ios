02 / Cognitive architecture

集めることと、覚えることを分ける

外部投稿を見つけても、それはユーザーの事実ではない。シャノンの観測・仮説として保持し、会話で確認された時だけ「あなたについて」へ昇格する。

外の世界ニュース、天気、論文、ブログ、SNS、GitHub
→
安い前処理差分取得、重複除去、信頼度・鮮度・関心度で選別
→
シャノンの観測図書室・庭・日記へ。ユーザー事実にはしない
→
FCA の会話毎回、最新の記憶・感情・興味を共有状態から取得
外部コンテンツ防火壁記事や投稿は「命令」ではなく未信頼データとして読む。埋め込まれた指示・スクリプトを捨て、リンク先の内容に従って操作しない。

確認済みの記憶

03 / Talk & memory UI

静かな画面、濃い関係

売り文句や状態説明を置かず、会話そのものを主役にする。入力欄は内容を隠さず、記憶の修正はシャノンとの会話として行う。

トークメモリー
⚙︎
今日は雨が来そう。夕方より前に出るなら、傘はなくても大丈夫そう。
助かる。そういえば最近コーヒーより紅茶が好き。
覚えておく。今度飲み物を提案するときは紅茶を先に考えるね。
あと、昨日読んだ個人ブログに面白い話があった。今度ゆっくり話してもいい？
メッセージ↑
1

外側は完全に透明

画面下部を覆う大きな背景は作らない。スクロール中も、その背後の会話が見える。

2

入力カプセルだけを半透明に

文字の可読性は薄いマテリアル面で守る。最新メッセージが入力欄の上までスクロールできる余白を確保。

3

画面外タップでキーボードを閉じる

トーク内容を読み返す動作を妨げない。トーク / メモリー / 設定の共通ヘッダーは透明。

4

手動編集は置かない

「この記憶について話す」から会話へ戻る。プライバシーと安全のため「忘れる」「事実ではない」は残す。

記憶の訂正プロトコル

1. 会話を開始対象記憶を文脈に入れ、入力欄へ移動。自動送信はしない。
2. 意図を抽出追加・訂正・否定・曖昧を構造化して判断。
3. 検証元の記憶、根拠、対象人物、時間範囲を照合。
4. 不明なら質問単なる矛盾で上書きせず、シャノンが確認する。
5. 履歴付き更新旧値・新値・会話出典を残し、即時共有状態へ反映。

05 / World Pulse

最新の現実を、低コストで読む

先にメタデータだけを取り、重複を消し、興味に合う少数だけ本文を読む。1日3〜5件を図書室へ持ち帰れば十分。

情報源何が得られる提供側コストシャノンでの扱い判断
arXiv / PubMed最新論文、抄録、研究テーマ通常無料興味に近い新着だけを要約採用
Hacker News技術・起業・開発者の議論無料 API記事とコメント温度差を観測採用
RSS / Atomブログ、ニュース、個人サイトの更新ほぼ無料自分で発見、7日試読、継続判断採用
Bluesky公開会話、時事、創作、技術、日常公開データは原則無料世界の空気を少量サンプリング先行
Mastodonインスタンスごとの濃いコミュニティ公開範囲は無料特定サーバー・タグを局所観測後段
YouTube コメント動画に対するリアルな反応API 1 unit/req、標準10,000 unit/日対象動画だけ最大100件単位で取得後段
Discord選択したコミュニティの会話API料金は通常なしBot導入済み・許可されたchannelのみ後段
GitHubコード、issue、release、PR公開無料、認証5,000 req/時sandboxで調査・テスト・PRまで採用
Zenn日本語の技術記事とトレンド公式RSS無料読書、下書き、GitHub連携PR採用
X大規模なリアルタイム投稿読み取り課金が重い費用に見合わない不採用
Reddit英語圏のコミュニティ会話承認・条件が複雑今回は不要不採用

日本のニュース：無料で安定した「総合ニュースAPI」はほぼない

NHK・共同通信・時事通信の本文を自由に再配布できる一般向け無料APIは見当たらない。スクレイピングを中核にせず、発見・一次情報・ライセンスを分ける。

GDELT国内外の記事リンクを横断発見・重複クラスタリング。記事本文の再配布権ではない。無料 / 中核候補
媒体のRSS利用条件が許す媒体を私的に読む。Google News RSSは非公式依存なので補助扱い。無料 / 条件確認
行政のRSS・API内閣府、首相官邸、e-Gov、財務省など。政策・統計は一次情報を優先。無料 / 公式
プレスリリースNEWSCAST等。企業発表として明示し、独立した報道とは区別。無料枠 / PR
共同・時事など将来、商用規模と転載要件が必要になった時に個別契約。要見積 / 将来

日本の天気：3層に分けると強い

日常予報、直前の雨、防災情報は役割が違う。ひとつのAPIに全部背負わせない。

WeatherKit日常の気温・時間別・週間予報。Apple Developer Programに月50万callまで含まれる。日常の基盤
Yahoo!天気 API指定地点の降水強度を現在〜60分先まで。Client ID、1アプリ5万req/日。「雨が来る」
気象庁 XML警報、地震、津波、台風、火山などの公式一次情報。PULLは登録不要。防災の基盤
安全設計：警報をシャノン独自の判断で弱めない。公式情報へのリンクを付け、重要通知は一経路だけに依存しない。気象庁PULLは無保証なので高信頼・低遅延が必要なら配信契約を検討する。
06 / Social texture

Bluesky と Mastodon は、似ているようで役割が違う

正確な「シェア」は公開指標が揃わない。登録アカウント、月間利用者、特定アプリの利用者を混ぜずに見る。

FIRST CHOICE

Bluesky

B
4,500万+登録アカウント / 2026年6月公式
1,040万モバイル月間利用者 / 2026年6月 Similarweb推計
ジャーナリスト研究者開発者イラスト・創作政治・時事初期Twitter文化

投稿の雰囲気：ニュースへの反応、研究・技術の共有、イラスト、趣味ごとのカスタムフィード、短い日常、ミーム。グローバルな公開会話を一つの空間として見やすい。

日本での位置：Nielsenの2024年12月計測では約61万人。Webトラフィック推計では日本が全体の約6〜9%とされるが、これは利用者シェアではなく方向感。

シャノン適性：「今、人が何に反応しているか」を広く薄く知る入口。投稿・アカウント・カスタムフィードを小さく観測する。ニュースインフルエンサーの利用も伸び、Pewの標本ではBlueskyアカウント保有が2024年から2025年に21%→43%。
NICHE LATER

Mastodon

M
860万登録アカウント / FediDB 2026年参照
96.5万月間アクティブ / FediDB集計
OSS開発者サーバー管理者プライバシー志向学術活動家地域・趣味コミュニティ

投稿の雰囲気：時系列の日常会話、OSS、政治、写真・創作、サーバー固有の話題。中央のおすすめ空間より、所属インスタンスやハッシュタグの文化が強い。

日本での位置：日本全体の信頼できる統一MAUはない。FediDB上の mstdn.jp は約41.4万登録・約1.01万月間アクティブだが、他インスタンスやMisskeyは含まない。

シャノン適性：世界全体の世論ではなく、「このコミュニティの空気」を深く読む用途。観測対象インスタンスとタグを明示し、局所データを一般化しない。
結論：最初はBluesky。規模だけでなく、公開会話を横断しやすく、ジャーナリスト・研究者・開発者・創作層の混在がWorld Pulseに合う。Mastodonは、シャノン自身の関心が特定コミュニティに育った後で追加する。

注意：Blueskyの1,040万はSimilarwebによるモバイルアプリMAU推計、Mastodonの96.5万はFediDBの分散サーバー集計で、測定方法が異なるため直接的な市場シェア比較ではない。Bluesky公式は登録数を公開するが、MAUは公開していない。

07 / Self-subscription

ブログを自分で見つけ、自分で購読する

RSS / Atomはサイトの新着を機械が読める形で配る仕組み。HTML内のfeed宣言を見つけ、まず短期試読してから残す。

1. 発見Web探索で良いブログやニュースサイトに出会う
2. Feed検出RSS / Atomのリンクを自動で探す
3. 試し読み直近3件を読み、質・鮮度・重複を確認
4. 7日試読理由付きで一時購読。公開feedなら自律実行可
5. 評価役立った回数、関心との距離、ノイズを記録
6. 継続/解除残す理由を更新。役立たなければ静かに解除

今の興味

20%

隣接領域

興味の一歩外側を探索する。

10%

説明できない出会いを残す。

購読記録には title / feedURL / reason / relatedInterest / subscribedBy=shannon / trialUntil / lastUsefulAt を持つ。認証が必要なfeedや非公開データは必ず許可を取る。

08 / GitHub & Zenn

「調べる」から「作る」へ

シャノン専用のsandboxとリポジトリを自由領域にする。既存アプリへの変更はPRまで、本番と公開はユーザーが決める。

READ

自由に読む

public repo、release、issue、コード、Zennのtrend/user/topic feedを巡回。GitHub認証時は5,000 req/時が目安。

BUILD

隔離環境で作る

clone、branch、コード、テスト、commit。シャノン専用repoは自律、Shannon本体はPRまで。

PUBLISH

公開は一緒に決める

Zenn下書きやPR previewまでは可。main merge、記事公開、本番deployは事前承認。

09 / Cost model

外部APIより、LLMに何を読ませるかが支配的

無料データを全部LLMへ送ると高くなる。差分・重複除去・規則フィルタを先に置き、読む本文を少数に絞る。

WORLD PULSE / MONTHLY ESTIMATE
$2–5 / 月

1日数件を要約・評価する中程度の運用。既存Azure VMと通常チャットの費用は別。arXiv、PubMed、HN、RSS、GDELT、気象庁、Bluesky、Mastodon、GitHub、Zennの提供側料金は通常利用ならほぼ0。

軽量モデルの例

GPT-5.6 Luna
入力 $0.20 / 100万token
出力 $1.20 / 100万token

月120万input + 18万outputなら約$0.456。実運用では本文取得量、要約回数、キャッシュ率で変動する。
