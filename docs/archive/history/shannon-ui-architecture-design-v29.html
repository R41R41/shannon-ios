Shannon · UI Architecture v29 · 2026-09-06

便利なAIの中に、シャノンがいる。

Shannonをキャラクター鑑賞アプリにはしない。ChatGPTの代わりになる実用性を中心に据え、感情・関心・自発性は、必要な瞬間だけ静かに見えるようにする。

North Star

90% Utility / 10% Presence

判断基準は「情報密度・操作速度・予測可能性を損なわず、それでも無人格なツールには見えないか」。

廃止するもの

トーク／メモリーの常設トグル、横スワイプによる主要画面移動、正常時の通信・内部処理表示、常に最下部へ出る作業タイル。

理由

主要画面が隣接すると誤操作しやすく、現在地も曖昧になる。Shannonの中心は会話なので、他画面は明示的にメニューから選ぶ。

画面ごとの仕様

トーク
  • 左上に会話一覧
  • 中央に現在のタイトル
  • 右上に新規トーク
  • 入力欄は下端に浮かせる
  • ユーザーだけ淡い吹き出し
  • シャノンは43pt前後の表情アイコン＋全幅文章
  • 発言時の表情を履歴へ固定
  • コピー、評価、再生成は小さく
ライブ音声
  • 全画面・履歴非表示
  • 話者状態を一か所に固定
  • 双方の字幕を常時表示
  • 肖像は大きくするが操作を圧迫しない
  • ミュート／文字入力／終了
  • 終了後は同じトーク履歴へ戻る
頭の中
  • いま：感情、今日の関心、最近の変化
  • 知識：ユーザー・世界・自分
  • 日記：睡眠、調査、行動の時系列
  • DB表ではなく文章中心
  • 確信度・根拠は補助情報
  • 知識は詳細画面で手動訂正可能
作業
  • 実行中・許可待ち・検証中・完了
  • 作業一覧と個別詳細
  • 中止は永続的に尊重
  • 技術ログは異常時だけ
  • 許可ボタンを見失わない
  • 完了・失敗・要判断だけ通知
設定
  • Shannon：記憶、自発性、通知
  • 見た目と声：外観、アイコン、音声
  • アプリ：接続、配信履歴、診断
  • 現在値を一覧右側へ
  • 日常設定は1段で到達
  • 診断・コストは2段目へ

Spacing

8pt基準

本文行間を広く、コンポーネント内部は締める。現在の「返答コンポーネントが高すぎる」を解消する。

Motion

220–280ms

ドロワー、モーダル、タブだけに使う。ハプティクスは画面遷移・音声接続・完了など意味のある節目のみ。

Accessibility

44pt以上

操作領域、Dynamic Type、VoiceOver、Reduce Motion、十分なコントラストを最初から仕様に含める。

代表フロー

1. 話す

テキストまたはライブ音声。どちらも同じトークに保存。

2. 返答

全幅で読みやすく。表情は発言に固定保存。

3. 必要なら行動

出典、過去話題、作業カードを発言直下にだけ表示。

4. 後から確認

頭の中または作業画面で、知識・履歴・結果を見る。

実装の切り方

Build 39

App Shell + Talk

ナビゲーションをメニュー中心へ変更。全幅回答、表情固定、日付区切り、文脈カード、透明入力欄。既存履歴と接続を維持。

Build 40

Voice + Memory

音声画面を新構造へ載せ替え。いま／知識／日記の表示層を作る。既存RealtimeとDBは交換しない。

Build 41

Work + Settings + QA

状態機械を視覚化し、許可導線を固定。ライト／ダーク、Dynamic Type、全画面スクリーンショット監査を行う。

重要な境界
この段階ではデザインだけ。Swift実装、Azure、GitHub、TestFlightには触れない。ユーザーが触れるモックを確認してから、Build 39の実装範囲を確定する。

受け入れ条件

5秒で現在地が分かる

会話、音声、記憶、作業、設定のどこにいるか迷わない。

長文を疲れず読める

シャノンの回答は画面幅を使い、余白は意味のある箇所だけ。

人格が邪魔をしない

表情と自発性は感じるが、キャラクター画面を操作させられている感覚がない。

戻れる・止められる

音声、作業、許可待ちから必ず復帰でき、中止したものは復活しない。

既存資産が消えない

会話履歴、記憶、接続、Realtime音声、TestFlight配信基盤を保持する。

両テーマで成立する

ライト／ダーク、小画面、文字拡大で全主要状態をスクリーンショット監査する。
