Shannon delivery architecture · v17

Macを閉じても、
ShannonをiPhoneへ届ける

実現可能。Azure VMからiPhoneへ直接書き込むのではなく、コードをクラウドへ渡し、Appleのクラウドでテスト・署名し、TestFlight経由で更新する。

Macが起動中

今の方式で可能

USB、または初回ペアリング後の同一ネットワーク経由でXcodeから直接インストール。

Macが閉じている

Xcode Cloudなら可能

クラウド上のMac環境がビルド、テスト、署名、TestFlightへの配布を担当する。

Azureだけで直接配布

不可

iOSの正式な署名・配布にはAppleのビルド／配布経路が必要。Azureは指示・コード・状態管理を担当する。

大事な境界

  • 「コードを直してよい」と「iPhoneへ配布してよい」は別の承認にする。
  • 通常の会話や自発探索から自己改修を開始しない。
  • 本番配布ブランチへ直接書き込まず、テスト成功後だけ昇格させる。
  • 秘密鍵・APIキー・Apple認証情報をGitや会話へ保存しない。
  • TestFlightの自動更新を有効にしても、iOS側の更新時刻は完全には指定できない。緊急反映はTestFlight画面から手動更新する。

現在地

署名Apple Team設定済み。現在の開発用プロファイルは2027年9月まで有効。 App IDcom.r41r41.shannon Gitローカルリポジトリには現在リモートが未設定。まず非公開リモートへ安全に整理して登録する必要がある。 配布現在はMacからの開発用直接インストール。TestFlight／Xcode Cloudは未接続。 費用Apple Developer Program会員にはXcode Cloud 25 compute hours／月が含まれる。小規模な個人開発ならまずこの枠で試せる。

導入順序

Phase A — ソースを安全にクラウド化
現在の大きな未コミット差分を整理し、秘密情報を除外して非公開Gitリポジトリへ登録。保護ブランチを作る。
Phase B — TestFlightを一度手動で開通
App Store ConnectにShannonのアプリレコードと内部テスターを作成し、最初のビルドを配布。iPhoneにTestFlightを入れる。
Phase C — Xcode Cloudを接続
テスト、アーカイブ、内部TestFlight配布のワークフローを構成。ビルド番号をクラウドで一意にする。
Phase D — Shannonの改修タスクと連携
ユーザー承認後だけリリース用ブランチへ昇格し、Xcode Cloudを開始。結果をShannonの作業カードへ返す。
