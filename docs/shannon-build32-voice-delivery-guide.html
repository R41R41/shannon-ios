SHANNON / NEXT TESTFLIGHT

音声を安全に渡す
次回ビルド

Build 31でクラッシュしていた「最初の録音データを解析処理へ渡す境界」を作り直しました。配信時には、検証済みの新しい固定アプリアイコンとアイコン選択プレビューも同梱されます。

何を直したか

録音エンジンが一時的に貸す音声データを、別処理へそのまま渡さない構成にしました。

マイク入力
有効な間に独立コピー
安全な解析入力へ変換
非同期で文字化
  • Build 31の手書きメモリコピーを撤去
  • Appleの安全に受け渡せる解析入力だけを非同期処理へ送る
  • 待ち行列は最新4件に限定し、滞留し続けない
  • 音声・文字起こし・会話本文は診断ログへ保存しない

配信前の確認結果

  • 音声データの所有権を直接検証する新テスト：成功
  • iOSテスト 74件：成功
  • APIテスト 161件：成功
  • 統合試験、iPhone向けDebug／Releaseビルド：成功

ここまでがローカルで確認できる範囲です。クラッシュ解消の最終判定はTestFlight実機で行います。

次に必要な操作

1
配信を許可する
この会話で「GitHub送信と次回TestFlight配信を許可します」と伝えてください。Shannon Release Runnerで検証、送信、Xcode Cloud、内部配信まで一貫して進めます。
2
TestFlightから上書き更新する
更新が表示されたらそのまま更新してください。iPhoneをMacへ接続する必要はありません。アプリを削除して入れ直す必要もありません。
3
短い音声で一往復する
マイクを押し、短く話し、文字化、送信、シャノンの返答、読み上げ、停止まで確認します。

成功の目印

  • マイク押下後も画面が落ちず、「聞いている…」へ進む
  • 話した内容が入力欄へ入り、送信できる
  • 返答の読み上げと停止が動く
  • 既存の会話履歴とShannonへの接続が残る
  • 新しい固定アイコンと、設定内のアイコン画像プレビューが見える

失敗したときの安全な戻り方

アプリを削除しないでください。 既存の会話キャッシュと端末の接続情報を守ります。

  • 更新が出ない：TestFlightを開き直す。こちらでビルド処理と内部割当も確認します。
  • 再びクラッシュ：Shannonを開き直し、設定 → 音声診断 → コピーをこの会話へ貼ります。
  • 文字化だけ進まない：通常の文字入力が使えることを確認し、そのまま利用できます。
