Shannon · UX architecture audit · v21 · 2026-09-05

スワイプを減らし、
居場所を分かりやすくする。

画面遷移を軽快に見せることと、誤操作なく理解できることは別。Shannonでは会話中の文字選択・縦スクロール・キーボードが中心なので、横スワイプへ複数の意味を持たせない。

推奨案トーク／メモリーはタップ切替設定は独立画面スレッドはボタン＋端スワイプ
01 / Main decision

横に3ページ並べる構造をやめる

トークとメモリーは兄弟だが、スワイプ対象にはしない。上部の切替をタップした時だけ短いクロスフェード／方向感のある遷移を行う。設定はコンテンツではなく管理画面なので、歯車から独立したNavigationStackまたは全画面シートとして開く。
CURRENT

横長ワークスペース

トーク ←→ メモリー ←→ 設定

右スワイプがページ移動とトーク一覧の両方を意味し、開始位置や現在ページで結果が変わる。

→
RECOMMENDED

明示的なRoot Shell

［トーク｜メモリー］をタップ切替。設定は歯車。トーク一覧は一覧ボタン、端スワイプは補助操作だけ。

02 / Architecture

新しい画面階層

Root Shell共通ヘッダー、トーク／メモリー切替、作業バッジ、設定ボタン。選択中の画面だけを描画する。
Talkスクロール表示／対話表示、入力欄、スレッド一覧。表示モードはTalk内部の状態であり、アプリ全体のナビゲーションではない。
Memory「いまのシャノン」「知識」「日記」の入口。詳細はNavigationStackで奥へ進み、戻る操作にiOS標準を使う。
Settings歯車から開く独立画面。接続、外観、アイコン、アプリ更新、将来の音声設定をまとめる。
Transient UIエラー、再試行、作業中、承認要求は画面遷移にしない。Snackbar、Capsule、Task Roomとして一時表示する。

04 / UX risks

ほかに構造から直したい点

見えないジェスチャー依存

トーク一覧をスワイプだけにすると存在を発見できない。一覧ボタンを常設し、端スワイプは慣れた人向けにする。

タブの中にタブ

トーク／メモリーの切替直下に、メモリーの3分割Segmented Controlが続く。メモリーは入口カード＋詳細画面の階層へ寄せる。

透明すぎる固定UI

完全透明のヘッダーや入力欄は、背後の文字と重なる。外枠は作らず、内容が潜った時だけ薄いぼかし・グラデーションを出す。

小さな表示モード切替

スクロール／対話は意味の大きい変更なのに小さなCapsuleだけ。現在地より「押すと何になるか」を示し、設定の一部にはしない。

作業UIの競合

作業バッジ、作業Capsule、会話内カードが同時に出る可能性がある。緊急度に応じて一つだけを前面に出す規則が必要。

メモリーの情報密度

性格、コスト、評価、興味を同列カードにすると「頭の中」より管理画面に見える。内部指標は詳細へ退避する。

05 / Gesture policy

一つのジェスチャーに、一つの意味

操作役割採用
縦スクロールトーク・メモリー本文を読む。入力中はキーボードをインタラクティブに閉じる。採用
トーク／メモリーを横スワイプページ移動。スレッド一覧や文字選択と競合する。廃止
左端から右スワイプトーク画面でスレッド一覧を開く。画面全体の左半分ではなく端だけ。補助採用
一覧ボタンスレッド一覧を確実に開く。主操作
横スワイプで戻るメモリー詳細・設定詳細などNavigationStack内の標準戻る操作。標準のみ
入力中の横ジェスチャー誤遷移の原因。画面外タップまたは縦スクロールで入力状態を抜ける。無効
06 / Implementation order

v1.2を3つに分けて直す

v1.2.1 · SHELL

遷移の骨格

横ページングを廃止。タップ切替、独立設定、一覧ボタン、端スワイプ、全幅返信を実装。

v1.2.2 · CONTENT

各画面の階層

メモリー入口、対話モード、作業UIの優先順位、長文・空状態・失敗状態を整理。

v1.2.3 · DEVICE QA

実機で摩擦を除く

片手操作、キーボード、VoiceOver、大きな文字、ライト／ダークをTestFlightで一巡。

音声会話への影響：マイク、聞き取り中、読み上げ中をTalk内部へ追加できる安定したShellになる。画面横スワイプを先に廃止することで、将来の「スワイプで録音キャンセル」とも衝突しない。
