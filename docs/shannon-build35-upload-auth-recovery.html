Build 35のAppleアップロードを安全に復旧する

Xcode Cloudのビルド失敗ではありません。ArchiveとApp Store向け書き出しは完了しており、Apple側への最後の受け渡し認証だけが失敗しています。

判明したこと

  • Realtime音声実装、WebRTC、署名、Archive、IPA書き出しは正常です。
  • Build 34とClean Build 35は、どちらもXcode CloudのSession Proxy認証で同じ停止をしました。
  • Macにある旧API鍵は、Azureの現行配布鍵とは別物でした。そのためMacからの直接検証は401になりました。
  • Azureの現行配布鍵はApple APIへ正常に接続でき、Build 33を照会できています。

今回だけの復旧フロー

1Azureの現行鍵を暗号化SSHでMacの一時フォルダへ転送
2一時鍵を所有者だけが読める0600に固定
3取得済みの署名済みBuild 35 IPAをAppleへ検証・送信
4Apple ProcessingとShannon Internal割当を監視
5一時鍵を削除し、残っていないことを確認

ユーザーが行うこと

  1. Macのロック画面が出ている場合は、通常どおりMacへログインして画面を表示します。
  2. Codexへ「ロック解除しました」と返します。

鍵のダウンロード、コピー、ターミナル操作、App Store Connect操作は不要です。ロック解除後の確認とアップロードはCodexが続行します。

成功条件

  1. Appleの事前検証とIPAアップロードが成功する。
  2. Build 35が処理済みになり、Shannon Internalへ割り当てられる。
  3. TestFlightでBuild 35へ更新可能になる。
  4. Macの一時フォルダから秘密鍵が削除される。

失敗した場合の安全な戻し方

  • Build 33は現在のTestFlight版として残るため、既存アプリは壊れません。
  • Azureの本番API、DB、現行配布鍵は変更しません。
  • アップロード成否にかかわらずMacの一時鍵を削除します。
  • 認証が拒否された場合は連続再試行せず、Apple側の権限だけを切り分けます。

秘密鍵本体、API key、session、Apple固有IDはログやHTMLへ記録しません。
