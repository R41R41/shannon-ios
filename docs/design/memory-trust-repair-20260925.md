# 記憶・約束の操作導線修復

対象: iPhone / Mac 共用の「頭の中」。目的: 覚えた内容や約束を確認し、訂正・完了・取消・忘却・復元する。

| 保持 | 変更 | 変えない |
| --- | --- | --- |
| いま/知識/記憶の概要、日記、活動、既存詳細操作、意味色、標準NavigationStack | 概要データ量に依存しない「記憶と約束」入口と全項目一覧 | サーバー正本、API、外部アプリ承認、他画面の構成 |

入口は読み込み中・空・失敗・rich dashboardで常設。一覧は未完了の約束、終えた約束、保存中の記憶、忘れた/事実ではない記憶を区別する。各行は既存の詳細へ進み、変更後も同じIDを参照する。失敗時には前回の一覧を保持する。復元は物理削除の復旧ではなく、会話への利用を再開する操作として説明する。

検証: rich/empty fixtureの分類・全項目到達条件、完了/取消/訂正/忘却/拒否/復元のdurable反映、部品Light/Dark/大文字描画。実targetの画面遷移は別途確認し、未実施なら成功と扱わない。

## 検証の境界

- `ShannonMemoryLibraryTests` は通信なしの合成fixtureで、概要のデータ量と無関係な全項目の分類、変更後の再取得、通信失敗時の前回データ保持と再試行を確認する。サーバーの保存処理そのものをこのfakeで検証したとは扱わない。
- `ImageRenderer` で実際の入口ラベル・一覧行をLight/Darkで描画し、文字の欠け、状態が色だけで伝わらないこと、復元対象の区分を目視確認した。
- 親の `overviewContent` もrich/sparse双方で描画したが、native PickerやNavigationLinkはアプリホストのないImageRendererでは正しく描画されない。この画像は共有の親compositionが入口を含む構造証拠であり、完成画面や操作成功の証拠ではない。空画像を成功扱いしない画素検査を追加した。
- 大文字環境を注入した描画は行ったが、実iPhoneのDynamic Type、VoiceOver、キーボードフォーカス、画面遷移の確認は別途必要。

## 実アプリでの受け入れ手順

1. 「頭の中」で、現在の状態・知識・活動履歴が存在しても「記憶と約束」の入口が見えること。
2. 一覧で未完了の約束を開き、完了または取り消し後に戻ると「終えた約束」に同じ項目が移ること。再取得しても戻らないこと。
3. 保存した記憶を訂正し、再取得後も訂正した内容であること。
4. 記憶を忘れるか事実ではないと指定すると「忘れた・事実ではない記憶」に移ること。詳細から復元すると保存した記憶へ戻ること。
5. オフラインで更新・操作すると前回の一覧を保持しエラーを表示すること。復帰後の更新でエラーを解消できること。

上記は本番データを使わず、テスト用の記憶で行う。削除の復元と会話への再利用を混同しない。
