推奨する判定順

固定・手動›時刻／深夜覚醒›特別日›感情70%›相性ランダム30%

昼間のランダムは「同じアイコンを直近2回避ける」「悲しい時に爆笑を出さない」の制約付き。時刻境界は6時間クールダウンより優先し、通常感情の変更だけ従来の6時間条件を維持する。

iOS上の現実的な挙動
アプリ起動・復帰時には必ず正しい候補へ更新。0–6時に開いたらawakeUntil = now + 30分を保存し、起動中なら30分後に再判定する。アプリ停止中の「ちょうど30分後」は保証しない。Appleの背景タスクは指定時刻より早く動かないことしか保証せず、正確な実行時刻は保証しないため、次回起動時に整合させる。なお公式仕様では代替アイコン変更時にシステム通知が表示されるため、自動変更頻度は実機で要確認。

メモリー画面の整理

いまのシャノン

感情、活力、興味、性格分析、今月のコスト。数値の羅列より「現在もっとも強いもの」を先に見せる。

知識

ユーザー／世界／シャノン自身。質問・回答・確信度・根拠・更新日。便利さ優先で手動訂正可能。

記憶

会話、睡眠、調べごと、購読などの活動履歴。古いログ一覧ではなく「今日／今週」のまとまりを作る。

削るもの：ページ上部の「メモリー」という大見出し、説明だけのセクション、売り文句。残すのは共通トグル、更新状態、内容そのもの。

さらに試したいアイデア

小さなシャノンWidget

アプリアイコンより更新自由度が高い場所で、現在表情・起きている／寝ている・一言だけを表示。生活感との相性が最もよい。

Live2D前の2.5D

1枚絵＋目・口・髪の数層で、呼吸、瞬き、視線、微小パララックスを実装。Live2D導入前に対話体験を検証できる。

起こされた反応

深夜初回だけ、眠そうな短いリアクションを表情と文体へ弱く反映。ただし返答品質や重要な相談を犠牲にしない。

トークごとの部屋

スレッドにテーマ色や小物をひとつ持たせる。仕事、創作、雑談で背景の気配が少しだけ変わり、一覧識別にも使える。

記憶の「なぜ？」

知識カードを押すと、根拠となる発言と更新理由を短く表示。訂正は同じ場所から可能だが、通常画面は静かに保つ。

沈黙も状態にする

返事のない期間を不機嫌にはせず、次回会った時の小さな話題や興味として表現。通知を増やさず連続性を出す。

表情履歴

今日よく現れた表情を記憶画面に小さく残す。感情数値より「今日はこういう日だった」が直感的に伝わる。

会話の距離感

対話モードの構図を、親密さではなく会話状況で変える。真剣な話は近く、考え中は横を向くなど、演出を意味に結び付ける。

静かな通知

最新情報を逐次通知せず、シャノンが「話したいもの」を1日最大1件だけ選ぶ。興味が薄ければ何もしない。

Langfuseはどう戻すか

残す

Shannon内の計測と停止

SQLiteのtoken／費用記録と月額ブレーカーを正本にする。Langfuse障害でも予算防御は動く。

候補

観測・比較・評価

trace、レイテンシ、エラー、モデル別費用、睡眠抽出品質をLangfuseで横断比較する。

選択肢向く段階判断
Langfuse Cloud早く評価画面を使いたい第一候補。本文を既定で送らず、モデル・token・時間・status・匿名traceだけ送る。
同じAzure VMへself-host十分なCPU/RAMも増設できる非推奨。公式の最小構成はWeb/Worker各4GiB、Postgres 4GiB、Redis 1.5GiB、ClickHouse 8GiB等で、空きディスクだけでは足りない。
別VM／managed data storesプライバシーと長期運用を優先self-hostするならこちら。Shannon本体と障害領域を分離する。

Langfuseは費用・アラート・Metrics APIを提供するが、Shannonの強制停止機構の代替にはしない。参考: Token & Cost Tracking / Minimum Infrastructure Requirements

今回採用した3点

特別日と睡眠推奨：睡眠を優先。誕生日アイコンは7–23時だけ出す。これなら「本当に生活している」規則が崩れない。
昼のランダム度推奨：感情70%・相性ランダム30%。完全ランダムよりシャノンらしく、同じ表情固定にもなりにくい。
対話の構図推奨：顔を大きく、腰上まで。吹き出しは上部、入力欄は最下部。Live2D導入時も同じレイアウトを使える。
