01 / corrected thesis

守るのは画面ではなく、積み上がった資産

新しい前提：会話履歴、記憶、ユーザー知識、端末接続、Realtime音声、作業状態、アイコン資産は維持する。一方で、ナビゲーション、画面分類、コンポーネント、余白、色、モーションは、必要ならゼロから組み直す。
90% · 速い・明快・頼れるアシスタント10% · シャノンの気配

主役

質問、回答、調査結果、作業成果、次に必要な操作。キャラクター画像ではない。

人格の場所

表情アイコン、声、短い状態文、言葉遣い、自発的な一件、穏やかな動き。

入れないもの

好感度、親密度ゲージ、部屋、着せ替え中心、ログイン報酬、関係を煽る通知。

03 / component anatomy

部品の位置と色には、役割を持たせる

上部

  • 左：スレッドDrawer。チャットアプリで学習済みの場所で、戻る操作とも整合する。
  • 中央：現在のトーク名。アプリ名や感情メーターを置かず、いま何を開いているかだけを示す。
  • 右：新規トーク。高頻度で可逆な操作を一段目に置き、設定はDrawer内へ下げる。

会話本文

  • シャノン：吹き出しを使わず全幅。長文の行長と余白を確保し、ChatGPT／Claude型の読み物として扱う。
  • ユーザー：淡いsurfaceの短い吹き出し。誰の入力かを形で区別し、強いブランド色で塗らない。
  • 表情：返信先頭の40–44ptアイコン。感情名や数値は通常表示しない。
  • 出典：Perplexity型の小さなchip。タップで出典一覧を開き、本文には必要最小限だけ出す。

下部composer

  • キーボードの直上に固定し、Aetherと同じ半透明surface。背後の会話を隠す不透明な帯を置かない。
  • 左端の＋は写真・ファイル・参照をまとめる。文字入力中は右端が送信、空なら音声になる。
  • 送信だけを深い青のfilled circleにして、取り消せない決定点を明確にする。他の操作はneutral。

配色

  • 大面積はsystem background／neutral surface。水色を背景全面へ広げない。
  • 水色は選択、focus、リンク、進行中、シャノンの存在に限定する。
  • 暖色はシャノンの感情にごく少量。成功・警告・失敗はsemantic colorを使い、人格色と混ぜない。

モーションと触覚

  • Drawer、Sheet、音声接続、作業状態の変化など、空間関係の説明にだけ使う。
  • 感情の常時アニメーションはしない。表情切替、瞬き、呼吸は対話画面かWidgetへ限定する。
  • 選択・送信・モード確定には軽いhaptic、失敗は強い振動で叱らず文言と形で示す。
04 / apple references

Apple純正アプリは、目的別に見る

Messages

会話と入力

スレッド一覧、入力中の視線、添付入口、キーボード復帰、長押し操作。

Phone / FaceTime

Realtime音声

接続中・聞き取り中・ミュート・終了の優先順位。通話中は操作数を減らす。

Journal

記憶と日記

出来事を時系列で読み返し、写真・場所・音声などを一件へ束ねる。空欄を埋めさせず候補を出す。

Reminders

作業

今日・予定・完了を分け、詳細は必要な時だけ開く。作業状態を会話本文へ常駐させない。

Settings

設定

標準Formと階層、明快なラベル、破壊的操作の隔離。巨大な独自カード一覧を避ける。

Weather / Health

現在状態

一目で読む要約と、詳細データの段階表示。シャノンの今を数値ダッシュボードにしない。

06 / quiet personality

感情と自発性は、4か所だけに出す

返信アイコン

送信時の表情を固定。文章を読む邪魔をしない。

声と間

声色、短い相槌、発話の間で状態を感じさせる。

今日の一件

自発的な提案はInbox badgeと一件の短いカード。

Memoryの今

短い状態文、今日の関心、考えていることを表示。

人格はナビゲーションを増やす理由にしない。シャノンの感情が変わっても、ボタン位置、操作結果、情報階層は変えない。
07 / research method

次はスクリーン単位で分解してから描く

1. CaptureAether／Voyager実画面と、公式に確認できる各製品の代表状態を集める。
→
2. Annotate座標、余白、色、階層、片手操作、状態変化へ注釈。
→
3. Extract模倣ではなく、配置の理由と再利用する原則を抽出。
→
4. PrototypeShannonのLight／Dark主要画面をHTMLで比較。
→
5. Approve画面案をユーザー確認してからSwiftUI実装。
