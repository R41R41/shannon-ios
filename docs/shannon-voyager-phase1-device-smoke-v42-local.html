導入済み

「整理して」をiPhoneで確認する

対象 Shannon iPhone版 0.1.0 (Development 2)／commit d0000d1
導入方法 接続済みiPhoneへ既存アプリを削除せず上書き
サーバー Shannon Azure API反映済み
今回の到達点 候補作成・確認・編集・採用・除外・保留と、安全な未接続表示

目的

会話の中からVoyager Task候補を作り、あなたが内容を確認し終えるまで外部へ書き込まれないことを実機で確かめます。Voyager本番の専用接続はまだ無効なので、最後の反映だけは意図的に失敗します。

確認手順

1. 起動とデータ維持
  1. iPhoneでShannonを開きます。
  2. 既存のトーク一覧と会話が残っていることを確認します。
  3. 通常の短いメッセージを送り、シャノンから返答が来ることを確認します。

成功：再接続画面にならず、既存会話と通常会話が使えます。

2. 安全なテスト会話
  1. 新しいトークを作ります。
  2. 明日、ShannonとVoyagerの連携結果を確認したい。 と送ります。
  3. 続けて、メッセージ単体で 整理して と送ります。

成功：「Voyager Task案」カードが表示され、候補はまだ未確定です。

3. 確認操作
  1. 「編集」を押し、Task名を ShannonとVoyagerの実機連携を確認する に変えます。
  2. 「編集して採用」を押します。
  3. 複数候補が出た場合、残りを「今回は保留」または「除外」にします。
  4. 未判断の候補が残っている間、「採用したTaskを反映」が押せないことも確認します。

成功：判断状態がカードに残り、画面を閉じても同じトークへ戻れば復元されます。

4. 最終反映の安全確認
  1. 全候補を判断した後、「採用したTaskを反映」を押します。
  2. カード上部が 「一部未反映」になり、対象候補に 未反映: DESTINATION_UNAVAILABLE と表示されることを確認します。
  3. 「一部をVoyagerへ反映できませんでした。同じ内容で再試行できます。」と「同じ内容でもう一度反映」ボタンが表示されることを確認します。

これは今回の想定結果です。通信自体が例外で終わった場合だけ「Voyagerへ反映できませんでした。接続回復後に同じ内容で再試行できます。」という汎用文言になります。今回のようにAPIが候補ごとの失敗状態を返せた場合は、上記のより具体的な表示になります。VoyagerにTaskは作られず、採用内容と再試行情報はShannon側に残ります。

成功条件

  • 既存会話と接続が維持されている。
  • 整理して で確認カードが出る。
  • 編集・採用・除外・保留が動く。
  • 全候補を判断するまで最終反映できない。
  • 未接続でもクラッシュせず、再試行可能な説明が出る。

問題が起きたとき

  • アプリが起動しない：iPhoneのロックを解除し、Macとの接続を維持してください。アプリは削除しないでください。
  • 再接続画面が出る：そこで止めてください。既存のKeychain情報を消さず、こちらで接続状態を調べます。
  • カードが出ない：送信した文が単独の 整理して か確認し、同じトークで一度だけ再送します。
  • クラッシュする：再インストールやデータ削除をせず、発生した操作と時刻を教えてください。
