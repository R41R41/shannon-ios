Build 33でクラッシュは解消し、iPhoneが4.8秒・6.2秒のM4Aを正常に録音できることを確認しました。一方、その後の一括文字起こしは失敗し、そもそも会話のテンポと発話中字幕を実現できません。そこで、次版候補をWebRTCによるRealtime音声会話へ切り替えます。

ローカル実装・自動試験 完了 Azure / TestFlight 未反映

実現する体験

話している途中から見える

ユーザーの言葉を差分字幕で表示。「聞けているのか」が待たずに分かります。

シャノンがそのまま返す

送信ボタンを挟まず、発話の区切りを検知。返答音声と字幕が同時に進みます。

自然に割り込める

返答中に話し始めたらシャノンは止まり、最新の発話を聞きます。

データの流れ

iPhoneマイク音声をWebRTCで送る
Azure端末を認証し、状態・記憶・履歴を組み立てる
Realtime音声理解・返答・音声生成・字幕差分
iPhone音声再生と両者の字幕を逐次表示
既存トーク確定した一往復だけ保存し、感情・記憶を非同期更新

秘密の境界： OpenAIの標準APIキーはAzureだけが持ちます。iPhoneはペアリング資格情報でAzureへSDPを渡し、返された接続情報で会話します。

Shannonらしさを保つ接続

材料音声会話での扱い
固定人格最小のShannon Coreを通常会話と共有。
現在状態・感情接続開始時の確定済み共有状態を渡す。返答速度を待たせない。
今日の関心通常FCAと同じ日次プロンプトを利用。
トーク履歴対象スレッドの直近12発言だけを境界付きで渡す。
記憶更新確定した一往復を既存履歴へ保存した後、背後で感情・記憶を更新。
作業依頼音声中に完了を装わない。実行・許可・進捗の見えるTalkへ案内。

安全・費用・失敗時

明示起動のみ

常時待受けはしません。画面を閉じる、アプリが非アクティブになる、10分経過のいずれかで終了します。

本文を診断に残さない

ログは接続段階・安全なエラー種別だけ。音声・字幕・メッセージ・鍵は記録しません。

段階導入

Build 33の一括方式は診断用フォールバックとして残し、Realtimeの実機Smoke後に扱いを決めます。

初期モデル

gpt-realtime-2.1-mini + gpt-live-transcribe。まず安価な構成で自然さを実機評価し、聞き取りや会話品質が足りなければ上位Realtimeモデルと同じシナリオで比較します。

公開前に残るコスト制御

現在は端末単位の接続回数制限と10分上限まで実装。Azure側の日次Realtime予算と実時間ベースの永続メータリングは、一般利用へ広げる前の必須ゲートです。
