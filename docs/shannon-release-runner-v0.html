Build 31から使用可能

Shannon Release Runner v0

毎回のTestFlight作業を一から試行錯誤せず、検証から配信確認までを同じ順序で進めるための実行レーンです。既存のXcode CloudとAzure配布機能をそのまま使います。

一本化される流れ

1. 対象確認Shannonのmainと正確なコミットを確認
2. 自動検証API・iOS試験・Debug・Release build
3. 安全な反映同じコミットならpushを重複しない
4. Cloud buildXcode Cloudが署名・ビルド
5. 配信確認AzureがInternalへ追加しRunnerが完了確認

新しく作らないもの

TestFlightグループへの追加、10分間隔の新規ビルド検出、失敗時だけの通知、配信履歴はすでに実装済みです。Runnerはそれらを置き換えず、前後をつなぐだけです。

誤配信を防ぐロック

  • リポジトリが R41R41/shannon-ios でなければ停止
  • main以外、またはステージ中の未コミット変更があれば停止
  • 検証時と配信時のコミットが違えば停止
  • force pushは使わない
  • 外部配信は、その時点の許可を受けた後にだけ専用フラグで解錠

今回の操作

まずローカル準備だけを行います。この段階ではGitHubにもTestFlightにも変更を加えません。

scripts/release-runner.sh prepare

準備成功後、表示された正確なコミットと予定Build番号を使って、許可済みの配信を一本で実行します。

scripts/release-runner.sh run \ --expected-head <準備済みコミット> \ --expected-build 31 \ --confirm-external-release

成功の見え方

Build 31がShannon Internalへ割り当てられ、.build/release-runner/latest.json のphaseが distributed、outcomeが passed になります。

失敗したとき

  1. 同じコマンドを無条件に繰り返さず、JSONに残った停止地点を確認します。
  2. 検証失敗ならpush前なので、コードを直して再度prepareします。
  3. Cloud build失敗なら既存Buildには影響しません。Xcode Cloudの失敗箇所を直して新しいコミットで再実行します。
  4. 配信監視だけが時間切れなら、既存のAzureタイマーと設定画面の配信履歴を確認します。pushを繰り返す必要はありません。
