Response lane — ユーザーが待つ流れ

1 · Input

iPhoneから届いた発言とユーザーscope
→

2 · Capture

共有状態を一度だけ取得。実行中は不変
→

3 · FCA

固定prompt + 可変state + 直近20会話を固定LLMへ
→

4 · Reply

本文と、入力への軽量な反応表情を返す。共有状態はまだ変更しない

Background lane — 待たせずに変わる流れ

感情

快・不快、活性、開放性を連続値で保持。投稿アイコンは同じ法則で即時投影し、共有状態への反映は返答後に直列実行する。

次の感情 = 今の感情 + 減衰 + 刺激

記憶想起

今回の発言と過去経験の文字特徴を比較し、重なりと新しさから最大3件を活性化する。現在の返答には割り込まない。

関連度 = 意味の手掛かり × 0.88 + 新しさ × 0.12
順序同じscopeの更新は必ず直列。別scopeは独立。
影響完了した共有状態だけを、次のFCA開始時に取得。
興味現在の話題が想起された過去経験と共鳴したときだけ、Shannonの関心へ昇格。
v1の境界予測なし、Web検索なし、スキルなし、ユーザー情報の自動確定なし。

Persistence — 再起動を越える痕跡

共有状態

感情・興味・ユーザー情報・活性記憶を、scopeごとの不変スナップショットとして保存。

companion_states

会話

ユーザーとシャノンの発言、時刻、その投稿時の表情を保存。iPhone起動時に最大200件を復元。

conversation_messages

経験ログ

会話完了と状態変化を削除・上書きせず順番に追記。睡眠バッチが一日を再生する材料になる。

experience_events
FCAへ渡す会話保存件数とは分離し、直近20メッセージだけに制限。
障害時の順序LLM完了後、HTTP返却前に会話と経験を保存。その後に感情・想起を更新するため、背景処理に失敗しても会話は失わない。
データ境界scopeごとに状態・会話・経験を分離。DBと付随ファイルは所有者だけが読み書き可能。

固定部分と変わる部分

固定

「シャノン」という名前、状態と文脈から自然に会話すること、ユーザー固有情報は提示された根拠だけで扱うこと。LLMモデルもv1では固定。

可変

気質、連続感情、興味、睡眠バッチで確定したユーザー情報、現在想起中の記憶、直近会話。
