# 記憶と行動の信頼性修復 — 2026-09-25

配信済み `0b5c5a0` を基点とする `codex/shannon/trust-repair-20260925`。この作業は修正とローカル検証まで。本番DB、Azureの稼働コード、TestFlightは変更していない。

## 今回変える体験

| 不具合 | 修正後の振る舞い |
| --- | --- |
| 第三者の話、否定、引用を本人情報として覚える | 原発言の帰属を検査し、確証がないものは会話のまま残す |
| 忘れた内容が人格分析や古いキャッシュから再登場する | 元の証拠と派生記憶を照合し、回答へ渡す直前にも除外する。履歴そのものは削除しない |
| 訂正前の発言が睡眠処理で別の表現として再学習される | 訂正版を有効に保ち、元の証拠を再学習しない。古いAI返答もモデル向け文脈から除く |
| 「これ」「さっきの話」を文字どおり保存する | 同じトークの直前本人発言と出典IDに結び付ける。特定できなければ確認し、保存しない |
| 「覚えた」という返答と実際の保存が一致しない | 対応する参照保存コマンドでは、実際に会話記憶を固定できた場合だけ成功を返す |
| 「うん」「聞こえますか」が関心になる | 新しい抽出候補と、既存関心のモデル向け投影から会話ノイズを除く |
| 写真の話に無関係なプログラミング記事をつなげる | 関連する根拠がなければ見送る。「昨日の話につながる」等の裏付けのない回想を使わない |
| 活動履歴が増えると約束の操作が消える | 「頭の中」の先頭に「記憶と約束」を常設し、完了・取消・訂正・復元へ進める |
| 古い忘却対象が一覧の取得範囲から落ち、復元できない | 明示的な操作履歴がある対象は通常の一覧範囲の外でも管理可能にする |
| Discordの本人発言に対して個人アプリの記憶を公開の場へ投影する | 共有・不明な会話の個人記憶投影を既定で停止。サーバー設定で許可した1対1の完全一致IDだけ例外 |

ノート／タスクへの書き込みは従来どおり**提案と承認**を挟む。「ノートに反映済み」とは言わない。前述の参照解決は15分以内・直近8メッセージ中の直前本人発言に限定し、他トークを勝手に探さない。複数候補や「昨日の話」などは確認する。明後日・曜日・今週末の検出を揃え、週末の具体的な日付を捏造しない。

## 既存データの扱いと配布時の注意

- アプリDBのschemaは13→14。起動時に忘却の元証拠を補完し、人格分析・回答用投影を安全に再構築する。元の会話、事実、旧版分析は保持する。
- daily_mindには`grounding_version`を追加する。旧キャッシュは履歴を残して利用を停止し、同日の無限な再生成・追加課金を避ける。
- 本番移行前にDBの整合したバックアップを取得し、移行後に会話件数不変、禁止した内容が最終プロンプトにないことを確認する。schema14へ移行後の旧API単独差し戻しは不可。DB復旧は移行後の新規データを失うので自動で実行しない。
- APIとbackground/world workerを同じ修正版に揃える。古いworkerを並走させない。
- 既存platform bindingは共有扱いになる。個人記憶の共有が必要な1対1宛先は、受信者を検証してから`audience: owner-private`をサーバー設定に追加する。guild prefixには許可しない。
- 既にモデルへ送信済みの文脈（特に継続中の音声セッション）を、この修正だけで撤回できるとは扱わない。配布後の検証は新しいセッションで行う。
- 忘却・否定・訂正の時点より前のAI返答は、言い換えを含む依存元が追えないためモデル向けの再利用を停止する。履歴画面では引き続き読める。これは文脈の一部を失う保守的な措置で、将来は発言ごとの出典追跡で精密化する。

## 配布後、ユーザーにお願いする確認（今は操作不要）

下の「紅茶」は例。実際の好みに置き換え、訂正を試した後は正しい内容に戻す。

1. 新しいトークで「私は紅茶が好き」→「さっきの話を覚えておいて」。固定した記憶の内容が「さっきの話」ではなく、元の発言になっている。
2. 「頭の中」→「記憶と約束」で対象を開いて訂正する。再読込後も訂正版が残り、新しいトークでも古い内容へ戻らない。
3. 同じ対象を「忘れる」にした後、新しいトークでその内容を尋ねる。忘れた内容を断定しない。音声の場合もいったん終了して再開する。
4. 一覧の「忘れた・事実ではない記憶」から復元する。再読込しても操作結果が残り、会話履歴が多くても管理入口が消えない。
5. テスト用の約束を作り、詳細から完了／取消する。「未完了」から「終えた約束」へ移動する。
6. 「さっきの話をノートに残して」「これをタスクにして」。内容を特定できるときだけ正しい本文の**確認待ち提案**になり、曖昧なときは質問される。試験用の提案は内容を確認し、不要なら外部アプリへ反映しない。

各確認で失敗したら、端末・アプリbuild・発言・期待と実際の違いを教えてもらう。実会話を公開の場所に貼る必要はない。
