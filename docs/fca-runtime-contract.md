# Common FCA runtime — tasks, shared context, voice and bodies

Status: implemented on `codex/shannon/common-fca-runtime`, opt-in, not deployed. Design source: Syzygy `docs/architecture/shannon-fca-loop.md`.

## What runs

`configuredServerFca` attaches a durable Task Hub and one-step FCA runner to the existing API. `SHANNON_FCA_RUNTIME=on` explicitly enables it; absent/off creates no FCA connection, runtime tables, model client or polling loop. Stage4's existing mind worker is required and remains the sole scheduler writer. Owner-alone native text conversations attach a conversation task to their existing foreground respond lease. Their existing model, sentence stream and conversation writer remain authoritative. Correlated owner-alone cascade voice also binds to the existing foreground conversation task. Own-time keeps its existing execution path. Minecraft and avatar touch have separate opt-in body adapters as described below.

There is one ancestor task per scope. The same `runFcaStep` handles every child. Each task has its own goal, completion criteria, inbox and complete native model rounds. The first tool set is `task.create`, `task.list`, `task.get`, `task.send`, registered in the common tool registry and offered by the conversation runner only while a trusted foreground task identity is bound. Background tasks may also use the existing public `web.search` executor and shared `memory.search` / `memory.read`; private external reads are not enabled there. Parent/scope/operation identity comes from execution context, never tool arguments. These tools contact other tasks inside Shannon; they do not send messages to people.

A first-class API at `/v1/fca/tasks` supports GET list (offset) or one task (id), and POST commands `create`, `send`, `stop`, `resume`. It requires a paired principal in the configured owner scope and a fresh owner-alone check. The Minecraft device-token filter executes before this route. Mutation bodies cannot supply scope, parent or audience. Create takes title, goal, completionCriteria and requestId; send takes target id, message and requestId. Calls acknowledge durable admission rather than task completion. Responses expose task projections, never native history, signed thinking blocks or inbox contents. Existing action-thread stop and stop-all also stop the corresponding FCA task or ancestor and descendants, including dormant tasks.

## State, execution rights and recovery

- `agent_tasks` and `agent_task_events` remain canonical. Additive `fca_*` columns distinguish these from Agent Host tasks. FCA rows never enqueue Host start/steer/interrupt commands, never receive Host results, and never enter Host task-tree migration, offline/busy accounting or command-lease recovery.
- `fca_task_checkpoints`, `fca_task_messages`, `fca_task_history` and `fca_task_segment_receipts` hold subordinate state. The canonical authority and subordinate writes commit on one SQLite transaction. Task phase is derived: ready is queued; executing is running with an active step; waiting is running without a step; a known stop is paused/fca_stopped; unresolved execution is paused/fca_unknown.
- Each bounded segment obtains an existing `agentTask` lease with source `fca:<taskId>:<admissionRevision>` and a hashed per-task resource. Task ancestry is independent of action ancestry. Waiting commits and releases its segment; a dormant parent occupies no inference slot. The existing background limit remains two, leaving the existing foreground slot available. This slice does not add a competing lease manager or redesign concurrency capacity.
- Child creation and its initial context commit atomically; retry identity includes that context even after it has been consumed. Inbox receipt/wake is atomic. Message identity includes source, target and text; a conflicting reuse is refused. A message received during a model call remains available to the next round. A final answer with unconsumed new input cannot prematurely finish the task.
- History, result and the original segment-completion receipt are committed atomically. A lost finish response is recovered by exact lease read-back or acknowledgement reconciliation, never by rerunning the model/tool. No new segment starts while its predecessor has an undelivered receipt.
- A dispatched operation whose outcome was lost stays unknown and cannot auto-resume. A proven not-sent expired lease can safely return to ready. Cancellation is durably receipted only after local model/tool promises unwind; the original-lease outbox then reconciles the worker acknowledgement, including a request lost before it was applied. A task whose admission claim reply was lost can retry only a proven unsent, expired admission.
- Stops are persisted before cancellation. Descendants cannot start new work. Active tasks remain stopping until the model/tool promises unwind and the existing action owner acknowledges cancellation. Parent completion cannot orphan unfinished children; a completion proposal with unfinished children yields instead. Resume is explicit for known stops; unknown execution needs reconciliation, not a new attempt.

Initial engineering bounds are depth eight, 64 nonterminal direct children, 256 nonterminal tasks per scope, eight tool calls per decision, and 1 MB of native history per committed segment, with bounded replay and complete-round compaction described below. Five consecutive rounds in which every tool fails pause the task and its children for inspection, preserving the repeated-failure safeguard across segment IDs. These are bounded first-slice limits, not a claim that those values are optimal. The financial-budget redesign remains deferred; paid own-time FCA execution is not admitted.

## Model and observation

`anthropicFcaModel` makes one native Anthropic call per decision, with the shared Shannon persona. It returns task tool calls, a wait proposal or a completion proposal. Internal control-call receipts mean only that the decision was received; the runtime owns lifecycle acceptance. Provider-required content/signatures and matching tool results remain intact. There is no nested hidden tool loop.

The existing configured small-model credential policy supplies the key. `SHANNON_FCA_MODEL` can explicitly select a supported native 1h-cache model; the absent value uses the existing Haiku default. This first opt-in endpoint is not yet routed through the native app's primary-model switch. `cacheHaikuRequest` establishes mandatory one-hour caching; actual native usage is recorded to the existing chat usage ledger before cache validation. No read/write cache evidence means no accepted result. Unknown paid outcomes retain a conservative accounting estimate, and SDK retries are disabled. Deterministic cache tests establish request/receipt behavior; live cache hits and live cost for this new loop have not been measured.

Each segment has a distinct Observer run. Real context/native/LLM/tool/store spans carry task, parent, step, revision and operation correlation; output projection omits prompts, message bodies, native thinking/signatures and tool-result text. Observer remains a projection, not task authority. New task-tree UI/layout changes are outside this slice.

## Conversation, sources and scheduling

Each owner Talk has one conversation task under the single ancestor. The ordinary respond action supplies the lease: there is no second foreground model loop or completion-acknowledgement writer. Task tools preserve the existing session, deadline, streaming, tool receipts and gates. A successful task write suppresses a duplicate legacy Host proposal. A child is admitted durably during the conversation but cannot execute until the ordinary conversation writer commits its source experience. A failed source stops its unbound descendants. A lost/unknown foreground outcome is held for reconciliation, never replayed.

Only source-visible inbox messages actually rendered for a model turn are consumed. New input arriving during inference stays for the next turn. Sources include conversation/replay/profile identifiers and trusted private-tool read receipts; they contain no copied prompt text. Current owner presence and memory/forgetting controls are checked when a source is reused. Background steps pin their admitted source set so an unrelated newly pending message cannot discard a valid result. Private tasks are not projected through the old Host-task prompt/notices/routes. Canonical task authority is unchanged.

Background admission uses a durable ordinal of successful admissions, not message arrival time or creation order. Continuing tasks rotate fairly; pending segment receipts and unbound source tasks remain excluded. Conversation tasks never enter this background scheduler.

## Tool selection and research

One Jev request asks include/exclude for each allowed tool, using only names/descriptions plus the goal, state and recent results. Uncertain tools should be included. Invalid/missing answers or provider failure fall back to the full allowed catalog. The model always receives the full catalog metadata; only selected definitions are loaded. `tool_open` adds an allowed definition for the next decision without executing it. Selection is reused until relevant input, child state, catalog or a failed tool result changes it. The existing conversation difficulty questions remain separate from this single tool-selection stage.

The server keeps selection mode active even without Jev credentials (full-catalog fallback), so loss of Jev configuration does not switch replay protocols. Native selected-tool rounds keep a stable top-level declaration and use the installed provider SDK's inline additions/removals. Existing signed blocks remain intact within a replay epoch. Branch-local stage-1 signed history must enter an explicit public replay epoch before adopting the selected-tool protocol; automatic migration of such in-flight historical experiments is not claimed. Production has not enabled either slice. The public-web executor uses the current tool runner, secret check, model search provider and usage ledger. It does not acknowledge the outer FCA action before its complete native round commits. An unknown search outcome holds the original segment and is never automatically retried.

## Bounded working history

The history store retains append-only original complete rounds. Replay compaction selects an exact contiguous prefix by server-assigned round IDs, keeps recent whole rounds, and includes the actually committed lifecycle outcome. The summarizer receives public content, never thinking or signatures. Its native request follows the same one-hour cache, usage-before-validation, abort and no-retry policy as the decision model.

A summary installation checks the live lease, source visibility, summary revision, exact coverage and history tail. It starts an explicit new replay epoch: structured summary plus complete public recent-round transcript form one stable bootstrap message; old signed blocks stay in storage and are not reused under a changed prefix. New native rounds append unchanged to that bootstrap. The bootstrap and reset boundary survive restart. Current defaults are 64,000 native replay characters, 24 rounds, six recent rounds, 32,000 summary-input characters and eight compaction batches; oversized indivisible rounds are held explicitly instead of silently truncated.

## Shared emotion, prediction and memory (stage 3)

Each common FCA decision receives a versioned reading of the existing companion emotion, current feeling and source-visible recent causes/outcomes. There is one emotional state across tasks. `AffectCoordinator` uses the existing companion writer; `fca_affect_receipts` only deduplicates evidence by event ID and appraisal revision. Parent and child references to one event do not count twice; a changed appraisal applies its difference. Existing emotion transitions and decay remain authoritative. Emotion informs expression, caution and exploration, never facts or authority. Existing text/voice prompts read this same companion state; their established emotion-input path stays in place.

The native decision may include an optional inline `fca_context` block alongside actions or control decisions. It can declare a concrete pre-action observation, expected value and deadline, or appraise an already observed event. No extra model is required after each action. The server writes the expectation before dispatch and compares actual result fields/text deterministically; transport success is not the predicted fact. Missing evidence remains pending and then unobserved, not failure. Mismatch is not proof of causation. Free-text descriptions stay in FCA working/evidence records, not the closed numerical prediction ledger. The top-level native prefix and selected-tool replay protocol remain stable.

Evidence is fenced by the original live step/lease and becomes shared only after its exact canonical round commits. The committed lifecycle status, not a requested completion or `ok` receipt, decides whether a task actually finished. Evidence delivery uses durable retry receipts and never reruns the original action. Causes inherit both the original event's sources and the evaluating task's sources; another task pins that lineage before receiving it.

Recall starts from the goal, context and recent results alongside history preparation and tool selection. Deterministic recall is immediately available; optional existing semantic enrichment is bounded. Ordinary decisions do not wait for deep retrieval; explicit memory questions wait at most 1.5 seconds. Only IDs are cached, and each decision rereads current content, audience and forgetting controls. Late results can inform the next decision while the execution segment is live. Remaining retrieval is cancelled and drained before the segment's completion receipt is published; it cannot keep spending under a released lease. `memory.search` and `memory.read` remain available even if Jev's selection omits them.

Task observations and genuine completed summaries are proposed as `task.experience` through the existing memory outbox and single writer. They become searchable canonical experience events without a fake chat thread or another model call. Pure lookups and redundant waits are not independent episodes. Operation success is not whole-goal success; unobserved outcomes can be refined under the same episode identity. Episode, summary, fact, knowledge and external-read provenance follows recall and child/message propagation, including the ordinary conversation reader. Forgetting, correction, revoked reads and audience changes are checked again at use time; a process without a source resolver withholds derived private-read material. Overlapping provenance graphs are traversed with per-query memoization and cycle detection, so a long conversation does not repeatedly expand the same ancestors. Memoized source decisions do not survive the next query.

An indexed canonical-store check can prove that a scope has no task read-source provenance, allowing ordinary history to retain its fast path when no forgetting rules apply. An absent proof port is not that proof. The check reads current retained records rather than the FCA feature switch, so inserting a task episode or reopening with FCA disabled still enforces its source restrictions.

## Voice connection (stage 3)

The existing ASR → conversation/router → streamed response → TTS path remains the foreground executor. A capable client sends its stable utterance ID and `historyReceipt: "utterance-id"`; the same ID travels through the existing canonical history save. The Swift client scopes that ID per async turn rather than keeping a mutable global. Owner scope, device, thread and input digest bind the durable receipt. Duplicate generation is refused before another model call or task creation; a repeated history commit returns the original experience.

A generated turn stages its source and the exact inbox selection, releases its foreground binding, and holds descendants until the matching history commit. Newer input cannot steal the receipt. Failed generation stops unbound children; a played prefix can still be preserved by the existing partial-history path. **The receipt acknowledges canonical visible history, not completed audio playback.** No background task gains an independent speaking executor. Old clients, guests, uncertain speech, default OFF and a stopped root retain ordinary voice behavior without allocating an unfinishable FCA receipt.

## Minecraft and touch connection (stage 4)

`SHANNON_FCA_MINECRAFT=on` connects the configured paired Minecraft body to the common FCA. It requires the FCA runtime, configured body, Jev credential and Decisions credential. Its separate authenticated `/v1/body/minecraft/control` contract carries bounded world observations, concrete candidates, validated skill schemas and original operation receipts. The historical game-chat contract still carries no coordinates, inventory dump or screenshots. With the feature off its legacy conversation/request behavior remains intact. In common mode, the old request queue is not an execution fallback.

The same task loop selects `mc.*` native skill tools, `minecraft.observe`, and `minecraft.reflex`. There is no inner campaign/planning agent behind these tools. The paired adapter advertises concrete InstantSkills with bounded schemas; the server excludes planner, agent, script, arbitrary-command, chat and background-launch tools. Arguments are validated again at execution. Existing `minecraft.request/status/cancel` conversation tools refer to common tasks, preserving foreground source binding and owner-only visibility. Authenticated game-chat intent creates a task with the canonical incoming experience as provenance. Task, source and body binding are admitted atomically.

A task-owned observation monitor operates while the normal model or skill is awaiting a response. Jev checks danger, lack of progress and visual requests; an explicit reflex tool can also request a short session. The task publishes its objective, completion condition, current context and concrete candidate menu. The Decisions provider selects only a candidate ID. A session may make several sequential short choices without returning to Jev every time. Each choice uses fresh state and optionally a current/previous first-person image. Relevant target/item/precondition changes invalidate that choice; an unrelated observation update alone does not. Time, action count, inference count, image age and action duration are bounded.

Normal and reflex operations share the original task's existing action lease and Minecraft body resource. Handoff waits for an actual stop acknowledgement; cancellation intent is not proof that movement stopped. Reflex completion returns a new observation to the task; an old model decision or cancelled skill is never resumed automatically. Unknown physical outcomes hold the original operation and resource until reconciled. Inputs are released on cancellation, timeout and disconnect, but the API does not label an unacknowledged release as confirmed. Provider usage is recorded even for rejected or late responses. Decisions uses its own input-only pricing, with a conservative nonzero estimate when paid usage is unknown; live latency/cost remains unmeasured.

`fca_body_operations`, bindings and session receipts are subordinate operation journals, not new task or lease authorities. Commands are delivered once; a lost response or restart cannot silently reissue a movement, attack or placement. Frames and image bytes are ephemeral. Only the image from the current body connection is resolvable for inference. Remote references cannot cause URL/file fetches. Reflex outcomes feed the existing FCA evidence/memory pipeline and task inbox with stable event IDs, while Observer receives correlated bounded spans rather than private raw images/history.

`SHANNON_FCA_TOUCH=on` adds a Jev-selected native gesture to the existing touch ingress. It requires the common runtime, Jev and source-visible canonical memory. A new client advertises `fcaTouchV1`; old clients retain their local response. The existing touch burst, stance, emotion, experience and speech path remains authoritative. The extra selector chooses from registered physical gestures plus no-action; it does not infer who touched the avatar. Touch ID deduplicates event and reaction entrances, selection, claim and renderer invocation. `/v1/body/touch-reflex` claims once and `/v1/body/touch-reflex/report` reports applied/not_applied/unknown. **Applied means the renderer accepted an invocation, not completed motion.** No second TTS path is introduced. Forgetting, source visibility, device registration and current capability are rechecked before selection and claim.

Implementation verification is recorded below. Enabling these flags in production, installing a capable native build and running the paused Minecraft trial are separate rollout actions.

## Remaining migration

Stage 4 of the common-FCA migration is implemented and verified on isolated branches, distinct from ADR-0008's historical stage numbering. Sleep and simultaneous end-to-end validation remain stage 5. Existing own-time execution and its budget remain unchanged. Live cache/cost and deployment have not been measured or performed for this branch. The paused Minecraft trial remains paused.

## Verification and rollout

Deterministic tests cover concurrent decisions with real SQLite action admission, dormant-parent/child progress, scoped task messaging, lost wakeups, descendant stop acknowledgement, unknown outcomes, original receipt recovery, Host isolation, privacy at response time, native replay/cache accounting and Observer provenance. Relevant suites are `fcaTaskHub`, `fcaTaskRuntime`, `fcaHostIsolation`, `fcaTaskRoutes`, `actionThreadFcaStop`, `anthropicFcaModel`, plus existing action/tool/model regressions.

Before enabling in production: finish the next intended migration slice, review its authority/audience/forgetting and billing integration, back up the database, verify bounded real-model cache behavior and task outcomes, then use the existing deployment runbook. Disabling admission does not erase FCA data. Stop/reconcile admitted tasks before turning the feature off. Do not remove memory, pairing or canonical task rows as rollback.
