# Shannon iOS 0.1.0 (73) — Gemini Live native microphone capture

## Incident

Build 72 no longer crashed and completed the Gemini audio-engine setup, but the
physical iPhone still produced no Gemini input transcript or reply. Diagnostics
ended after `gemini.audio.player.started`, without evidence that microphone PCM
had reached the WebSocket.

## Root cause and repair

Gemini Live connected `AVAudioSinkNode` at 16 kHz even though Apple's sink node
does not perform format conversion. Shannon's proven OpenAI Live capture graph
keeps the sink at the Voice Processing I/O microphone's native format.

Build 73 now mirrors that working graph: it captures native Float32 microphone
frames from Voice Processing bus 1, selects the first channel for interleaved
input, resamples after capture to mono 16 kHz PCM16, and sends 100 ms chunks to
Gemini. Gemini/Aoede voice, server VAD, subtitles, barge-in, resumption, backend
delegation, history, cost display, and the other voice modes remain unchanged.

Privacy-bounded checkpoints now distinguish native capture start, first queued
PCM chunk, and first successful WebSocket audio send. They record only format and
byte-count metadata—never audio, transcripts, messages, tokens, or credentials.
