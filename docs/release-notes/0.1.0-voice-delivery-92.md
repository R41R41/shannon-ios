## Defect and fix

The old single completion gate covered generation, TTS and a PCM-duration sleep. Audio-only failure or barge-in during that wait retained the entire already-answered input. The stream reader also waited for EOF after the terminal completed event, allowing a later connection reset to invalidate a valid reply.

Complete validated replies now handle their frozen input prefix as soon as visible. Their history writes run independently of playback cancellation, and subsequent generation waits for the preceding write to settle. Incomplete generation still retains the original input and its additions/corrections. Audio-only failure keeps the complete text available and never asks to regenerate the input. Partial generation/audio is explicitly reported as unfinished; generated/scheduled audio is never claimed as actually heard.

Native playback is drained using dataPlayedBack callbacks. Stop invalidates old tickets before AVAudioPlayerNode emits completion callbacks; waits resume on cancellation and have a bounded stall watchdog. FIFO and one-sentence prefetch remain unchanged. Content-free response correlation, completion, interruption and failure-stage/category diagnostics are added. Azure releases audio iterators on cancellation without misreporting deliberate caller abort as a provider failure.

## Verification and delivery evidence

Focused deterministic regression: 15 Swift tests (10 new delivery/stream/drain tests plus the existing ledger/prefetch tests), five API scope/abort/cleanup tests, API typecheck, fast gate. Full verification and actual release/device gates are recorded in the app-owned Syzygy status, not inferred from these focused tests. No paid model evaluation or real conversation fixture is needed for this state/transport defect.

Synthetic DEBUG-only Simulator fixtures verify wrapping of the audio-only failure notice in Light and incomplete-generation notice in Dark without composer overlap; the screen contract links the captured evidence. These captures do not verify actual microphone use, acoustic playback, or TestFlight installation.

## Knowledge return

TI-KNOWLEDGE-SHANNON-VOICE-ACK-STATE: separate answer acceptance, history persistence and optional audio delivery. Only incomplete generation belongs in an unanswered-input ledger. Protocol completion and native dataPlayedBack are different boundaries; cancellation must not retroactively undo complete text, and invalidated native callbacks must not complete a replacement playback. The app-specific response/voice/guest contracts are not a shared runtime standard.
