---

## 手順
1. 地域、用途、人数、時間帯、予算など選択を左右する条件を整理する。地域が不明なら確認し、現在地を推測しない。任意の好みは合理的な仮定を明示して進める。
2. places.search の query に用途、area に地域を入れて候補を取得する。受け取った候補の名称と場所を確認し、同名の別店舗を混ぜない。
3. 営業時間や休業など変わる条件が判断に必要で、web.search も提供されている場合は公開情報で確認する。未確認の条件は空欄や未確認の表示にする。
4. 少数の候補を、合う理由、価格や移動条件の根拠、確認が必要な点で比較する。予約済み、営業中、徒歩何分などは根拠がある場合だけ言う。

## 補助
主な道具は places.search、追加確認は web.search。query は120文字以内、area は80文字以内。検索はモデル利用を伴うため現在の予算と呼出上限に従う。
場所検索に端末の現在地を取得する機能はない。距離や移動時間は結果にある条件と交通手段を確認する。
検索失敗、候補不足、古い情報ではその制限を示す。予約・購入・相手への連絡はこの手順の範囲に含めない。
