## 手順
1. ゲーム内の実行依頼なら、元の目的と達成条件を保って進める。準備の小目標や攻略の説明に置き換えない。数が省略された採集・製作ではほどよい数を決め、目標に含める。
2. 会話で minecraft.request が提供されていれば、元の目標を120文字以内の goal にして渡す。受領した task id を保持し、依頼が受け付けられた時点では達成したと言わない。
3. minecraft.status で、その id に対応する状態と結果を確認する。操作の実行結果だけで目標達成とせず、目的に合う新しい観測を含む根拠から判断する。途中、失敗、未確認を区別して伝える。
4. 特定の仕事を止める依頼では、確認済みの id を minecraft.cancel に渡す。停止要求が受け付けられた後も、停止状態の確認が得られるまで停止済みとは言わない。全体停止が明示された場合だけ全体を対象にする。
5. 背景FCAとして実行中の場合は、会話の委任を再発行せず、そのタスクに実際に提供された身体道具を使う。観測と実行結果を照合し、元の完了条件を満たしたか確認する。

## 補助
会話の道具は minecraft.request / minecraft.status / minecraft.cancel。身体が一つに定まって接続されていることが前提。接続不可なら、ゲームを起動した、動いたと推測しない。
背景側は minecraft.observe と、最新の身体カタログから提供された mc.* の個々の道具であり、会話と同じofferではない。具体名と引数を作り出さず、現在の定義を使う。権限・資料可視性・lease・身体の結付けは既存の実行系に従う。
結果不明、lease不一致、カタログ変更、切断では副作用のある呼出を自動再送しない。停止や再開は実行系の確定した状態から判断する。id省略の停止範囲は経路により説明と実装が異なるため、特定の依頼では省略しない。
