## 手順

ゲームに入る依頼、退出の依頼、サーバーの起動・停止、または自分の時間にマイクラで遊びたい時に使う。現在提供された道具だけを使い、管理対象は登録された serverId に限る。

1. minecraft.lifecycle_status で、新しいサーバー状態と自分の参加状態を確認する。管理側はゲームの体が不在でも連絡できる。状態が届かない、unknown、対象が一つに定まらない場合は操作済みと推測しない。
2. 「マイクラに入ってきて」など、入ることが目的なら、停止中と確認できた場合だけ minecraft.start を使う。起動済みなら起動し直さない。起動の結果はゲームへの参加と別なので、running を確認した後に minecraft.login を使い、joined の実行結果を確認する。起動だけを頼まれた場合には、勝手に参加まで進めない。
3. 退出は minecraft.logout を使う。absent の実行結果を確認するまで退出済みと言わない。退出しても管理の連絡口は残るので、ゲームを起動した状態と自分が入った状態を区別する。
4. サーバーの停止が目的なら、新しい otherPlayers を確認する。自分以外の人が入っている時は停止せず、その条件を伝える。人数不明でも停止しない。minecraft.stop はネイティブの停止直前にも人がいないことを一度のサーバー操作で検査する。入室が競合して refused になったら、人が入った状態として受け止める。stopped の確定した実行結果が得られるまで停止済みと言わない。オフライン認証のサーバーは自分のUUIDも人と区別できないため、先に自分が退出する。
5. 自分で遊びたい場合も、その一歩ごとに現在の own_time の権限・活動記録・停止設定・予算を保つ。会話の owner_request として依頼し直したり、別の実行系やシェルを起動したりしない。入ることは、他の人へのチャットや投稿の許可を増やさない。

## 補助

unknown、切断、期限切れ、停止確認の不足では、同じ操作を再送せず、新しいIDでやり直さない。元の実行結果の確認を待つ。現在状態が偶然目的と一致しても、不明になった元操作の成功証明にはしない。already_running / already_stopped / already_joined / already_absent は状態を保った確認済みの無操作として扱う。
